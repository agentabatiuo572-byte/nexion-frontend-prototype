# 试用到期提醒与读取恢复

日期：2026-10-30。适用正式 App 与其共享 H5 的全局试用轮询；独立 H5 Lite 不在本次范围。

## 提醒条件

「试用抵扣金与 UVT 已失效。」表示当前领取单刚由有效试用进入服务端确认的最终到期状态。不能仅因页面状态变成 `ended` 就发送提醒。

- 同一账号绑定内，之前已成功确认同一 `claimNo` 处于 ACTIVE、GRACE 或 EXTENDED，之后收到更高 `version` 的终态，且服务端明确返回 `endReason=expired`，才产生到期提醒。
- `endReason=expired` 是服务端已经完成最终到期处理的权威结果。手机时间、历史宽限快照、当前活动配置、`serverNowEpochMs` 与 `finishedAtEpochMs` 的时间差均不参与提醒判定；读取并发与服务器时钟差不能阻止真实到期提醒。
- 旧领取单缺少宽限快照时，服务端根据实际自动到期记录返回的 `expired` 仍是权威终态依据；客户端不补造历史期限。
- 只在前台、登录及业务循环条件允许且当前读取成功后展示。每个绑定内同一领取单只提醒一次；短暂隐藏期间已确认的到期事件在正常前台读取恢复后消费，不增加轮询或重试定时器。

## 恢复、取消与隔离

- 首次读取历史 FAILED/CANCELLED/已到期记录不补发「刚失效」提示。断网、超时、HTTP 503 或服务重启后恢复同一历史终态同样不提醒。
- 已确认的有效试用在断线期间真正到期，恢复后同领取单的新版本明确确认 `expired` 时提醒一次。恢复仍为有效试用、ACTIVE 进入 GRACE、延长后的最终期限未到，均不宣布最终失效。
- 手动取消、解绑取消、其他取消、已转购及未知结束原因不显示到期提示。旧服务器未提供结束原因时兼容展示状态并保持静默，不从 FAILED/CANCELLED 名称猜测原因。
- 读取失败仅在当前绑定内保留用于判断提醒的最近确认领取单、版本和生命周期状态；实时资格、金额、报价和交易权限仍清空并保持关闭。旧版本不能在错误恢复时重新授权。
- 换账号、退出重绑、同账号重新绑定和 A→B→A 都清除提醒证据及待消费事件。旧请求、另一领取单、陈旧版本和旧轮询的消费操作不能向当前绑定发送到期提醒。

## 服务端字段

`GET /api/trial/state` 及相同权威投影新增兼容字段：`endReason` 为 expired/cancelled/null，`finishedAtEpochMs` 为已持久化的关闭时刻/null。自动到期白名单映射由服务端负责；原始内部取消原因不直接作为前端协议。

本次只修复提醒与读取恢复，不改变领取、冷却、延长、取消、转购、资金结算或权限规则。

## 验证边界

行为回归执行实际 App 轮询与真实试用 Store，覆盖首次历史读取、断网/503恢复、断线到期、一次消费、取消与转购、期限一致性、延长、旧协议、账号与同账号重绑、迟到响应、陈旧版本、后台恢复及并发轮询。源码回归与 TEST 发布、真实页面操作及独立验收分别记录；模拟边界响应不代表真实账号自然跨期验收。
