# H5 与原生 APP 手机算力规则

状态：待主人确认的修改方案；产品业务代码尚未修改。本轮只交书面方案，不制作或交付可点演示。真实设备识别、原生后台运行与服务端任务调度须在实施阶段验证。

## 目标与基本事实

H5 是网页版，原生 APP 是安装在手机上的全功能版本。手机算力必须由绑定手机上的原生 APP 执行；H5 可以查看账户与设备，但不能登记、校准、激活手机算力、接手机任务或代替 APP 报在线。购买设备的任务与收益不依赖浏览器或手机 APP 是否在线。

主人原始要求的对应清单：

| 编号 | 必须实现的行为 | 规格归属 |
|---|---|---|
| R1 | H5 首次注册成功后进入下载 APP 引导 | WEB1 |
| R2 | APP 首次登录检查手机绑定与激活，未完成则引导完成 | APP1 |
| R3 | 换手机登录 APP 时，按后台配置决定是否允许更换及频率 | APP1、OPS1 |
| R4 | 禁止更换时，提示已绑定其他手机且不可更换，手机任务停止 | APP1 |
| R5 | 允许更换时重新校准并替换激活，原手机在激活槽则自动下架 | APP1 |
| R6 | 仓库里未激活的旧手机与当前手机不匹配时，不能上架激活 | APP1 |
| R7 | H5 老账号登录提示网页不能运行手机算力，默认不因网页登录继续运行手机任务 | WEB1、RUN1 |
| R8 | 同一手机的 APP 保持登录运行时，登录 H5 不影响 APP 手机任务 | RUN1 |
| R9 | 跨设备 H5 登录时检查原 APP 在线状态，在线不影响，离线停止手机任务 | RUN1 |
| R10 | 上述限制均不影响其他已购设备 | APP1、RUN1 |
| R11 | 取消 H5 登记手机算力及其奖励机制 | WEB1、RUN1 |

不变量：每个账号最多一台绑定手机、最多一个可执行手机算力实例；绑定身份、激活槽、任务执行权必须一致。登录会话共存，不因 H5 登录踢掉 APP。H5 浏览器身份不能充当手机安装身份。所有时间、换机次数、绑定版本与任务资格由服务端裁定，前端只展示。停止期不累计手机收益，恢复后不补发停止期收益；已购设备不进入手机策略分支。

## 待确认的最小补充口径

以下是为消除未定义边界给出的建议，不是已经生效的后台政策：

1. 换机频率采用“每次成功换机后至少间隔 N 天”，支持 N=0；不叠加每月次数等第二套限制。例如 N=30 表示间隔 30 天，该数字仅为说明，正式默认值由后台明确配置。配置缺失/无效时拒绝换机并允许重试读取，不推测为不限次。
2. 首次绑定不算换机；同一绑定手机下架后重新上架不算换机；更换成功才记次数和时间，失败、取消、重复请求不计。首次绑定后第一次换机也受 N 天间隔约束，基准是首次绑定时间；以后按最近成功换机时间计算。
3. 异机 APP 登录后先暂停手机任务，直到当前绑定手机在暂停发生后主动重新登录认证，或新手机成功替换。即使允许换机但还在冷却期，也保持暂停。旧 token、启动恢复、回前台、静默刷新及心跳都不能清除换机暂停；不得借旧 APP 仍发心跳绕过禁换提示。
4. “APP 保持登录”不等于已经被服务端判定离线。H5 登录不撤销 APP 会话；是否还能接任务由有效 APP 会话与执行在线状态共同决定。在线宽限先沿用现有 3 分钟作为候选值，服务端统一计时；H5 无权刷新该时间。同机打开浏览器本身不能造成任务被暂停，真正退出/失联仍按 APP 运行规则停止。
5. 不追回历史合法入账，不删除账单。切换政策后停止新增手机 H5 奖励/离线计产。普通注册礼包暂保留。已确认离线/退出、换机暂停或绑定失效时，建议取消尚未获得服务端完成确认的手机任务，不给未确认任务发奖；恢复后领取新任务，不能把旧任务转给新机。停止与完成确认以服务端原子事件先后为准，先确认的有效结果仍幂等结算，先停止则拒绝迟到结果。原有短暂电量/网络中断宽限保持原规则，不能跨绑定版本续跑。
6. 安装身份永久丢失时，本次不提供自动恢复或管理员强制解绑。可重试恢复原生凭据；无法证明原安装则保持待核验、暂停手机任务并保留账号其他功能和冷却记录。客服入口仅受理，不承诺直接解锁；如需人工安全恢复，另行确定证明材料与权限后实施。

#### [FEAT-WEB1] H5 注册、登录与下载引导

**① 用户故事**

作为通过网页版注册的账号持有人，我想明确知道手机算力需要安装 APP，以便安装后登录同一账号完成激活。作为使用网页版的已有账号持有人，我想查看设备状态，同时让仍在线的手机 APP 正常执行任务。

**② 验收（GWT）与异常路径**

- Given H5 注册成功，When 返回注册结果，Then 进入已有下载引导页；不创建可运行手机资产，不校准，不自动激活，不产生手机登记奖励。刷新仍是同一账号，不重复创建账号或奖励。
- Given H5 老账号登录成功，When 进入网页，Then 清楚提示“网页版不能运行手机算力，请在 APP 中使用”；其他网页功能按既有权限开放，手机卡片显示服务端真实运行状态。
- 异常1：Given APP 下载地址未配置，When 点击下载，Then 显示“下载地址暂未开放，请稍后重试”，不打开空地址/伪造地址；允许继续网页版和退出账号。下载地址读取失败显示重试。
- 异常2：Given H5 直接打开校准/激活深链或伪造请求，When 请求手机能力操作，Then 页面引导去下载 APP，服务端拒绝手机登记、校准、激活、心跳和任务领取；不能仅靠隐藏按钮。
- 异常3：Given 注册超时/账号已存在，When 重试，Then 先恢复注册结果或转登录；不能重复礼包入账。奖励变更只针对手机算力，不清零既有钱包或普通注册礼包。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填/默认 | 权威与约束 |
|---|---|---|---|
| carrier | app / h5 | 必填 | 登录服务确认能力，不能信任任意请求自报 app |
| appDownload | 已有下载配置 | 已有结构 | 使用既有官方链接来源；缺失可见报错 |
| nextAction | download / dashboard / phone-check | 必填 | 登录结果决定，H5 不返回 phone-check |
| phoneRegistrationReward | 不产生的账务事件 | 无 | 不是加一个金额为 0 的入账动作；旧手机登记入口和发放链一起退役 |

**④ 状态机 + 禁止动作**

H5 未登录 → 注册成功 → 下载引导 → APP 登录（离开网页）或继续 H5；H5 未登录 → 老账号登录 → 网页主页与能力提示。禁止 H5 进入可提交的手机校准/激活状态；禁止 H5 写 APP 在线心跳；禁止网页登录默认注销 APP。

**⑤ 交互原型（4 态）**

- 默认态：下载说明、官方入口与继续网页版；老账号主页展示手机算力能力提示。
- 空状态：无手机资产显示“在 APP 中激活手机算力”，不伪造一台已经激活的手机。
- 加载态：注册结果或下载配置核对中禁用重复操作，保留返回/退出入口。
- 报错态：下载未开放、网络失败、重复注册分别给出下一步，不把失败画成激活成功。

**⑥ 点击流矩阵**

| 触发 | 目标 | 结果 |
|---|---|---|
| 注册提交成功 | 手机 APP 下载引导 | 保留注册账号与推荐关系 |
| 下载 APP | 既有官方地址 | 无链接显示原因与重试 |
| 继续网页版 | H5 主页 | 手机功能限制继续有效 |
| H5 手机激活/校准入口 | 下载引导 | 不提交激活动作 |
| 重试/退出 | 当前配置重读/登录页 | 不新增账号或重复奖励 |

**⑦ 跨文档一致性**

复用注册成功页，不误用电脑 GPU 的 `/compute-share/download`。前端 §4 注册登录与 §6.11 手机任务同步；普通注册礼包继续引用原奖励定义。

#### [FEAT-APP1] APP 绑定、校准、激活和换机

**① 用户故事**

作为安装 APP 的账号持有人，我想用当前手机完成绑定和激活，并在更换手机时清楚看到是否可换、何时可换，以便避免旧手机资产被错误激活。

**② 验收（GWT）与异常路径**

- Given APP 登录且无绑定，When 完成当前手机校准并确认激活，Then 原子创建/确认当前手机绑定、占用一个合法激活槽并授权手机任务；刷新可读回同一结果。
- Given APP 登录且当前安装与绑定一致，When 手机已在激活槽，Then 沿用激活，不重复校准/发奖；若在仓库则引导本机上架，不消耗换机额度。
- Given APP 在 B 登录但绑定 A，且允许更换并满足间隔，When B 校准成功并确认替换，Then A 自动下架到仓库、旧执行权失效、B 绑定并激活；A 的历史账务保留。A 原来占槽则 B 原位替换。
- 异常1：Given B 登录但不允许更换，When 检查绑定，Then 提示“当前已绑定其他手机，暂不允许更换设备”，暂停手机任务，A 绑定与槽位记录保留；可以继续其他功能，已购设备状态与收益不变。
- 异常2：Given 允许更换但未到时间，When B 登录，Then 显示服务端计算的下次可更换日期与剩余时间，不开放提交；暂停手机任务，原资产保持原位。时间到后重新获取资格，不只解锁前端按钮。
- 异常3：Given 仓库手机资产归 A，但 APP 在 B，When 从仓库、详情、批量操作或 API 直接上架 A，Then 均拒绝且提示“这台手机与当前设备不匹配”；不能覆盖 A 的校准数据或当成 B 激活。
- 异常4：Given 校准失败/取消或提交超时，When 重试，Then 不提前下架 A、不消耗额度、不重复建立手机资产；提交结果未知时先按请求标识读回最终状态，再决定重试。
- 异常5：Given 首次绑定、本机仓库激活或 A 在仓库时的 B 替换激活，且无空闲槽，When 确认，Then 提示先释放槽位；不挤下已购设备、不先改变绑定。计数包含有效试用预留槽及仍占位的隐藏设备，复用已有上限。A 在槽时无需另找空槽，原位替换。
- 异常6：Given 两台新手机同时替换、政策被关闭或额度在校准期间变化，When 提交，Then 服务端校验最新策略与绑定版本，最多一台成功；失败一方读回当前设备，不能恢复已失效旧绑定。
- 异常7：Given 老数据缺少可验证身份或 APP 重装导致身份不可恢复，When 登录，Then 进入待核验状态，手机任务暂停并可重试/联系客服；不靠型号、IP或一份新本地 UUID 把历史资产直接认领，也不借重装重置间隔。

**③ 数据字典 + 生成规则**

以下是待落地的接口契约，字段名可与实际服务端约定映射；不声称现有 API 已提供。

| 对象/字段 | 类型 | 必填/默认 | 权威与约束 |
|---|---|---|---|
| appInstallationId | 不透明字符串 | APP 必填 | 服务端登记并验证安装持有证明；页面不可任意选值 |
| phoneBinding | accountId、installationId、assetId、version | 无绑定时 null | 服务端一账号至多一份有效绑定；version 单调增加 |

**④ 状态机 + 禁止动作**

| 当前状态 | 事件 | 后续状态/副作用 |
|---|---|---|
| 未绑定 | APP 登录 | 待校准，尚无执行权 |
| 已绑定本机且已激活 | APP 登录 | 依在线和原有电量/网络条件执行 |
| 已绑定本机但在仓库 | 点击激活且有空槽 | 本机激活，不记换机 |
| 已绑定异机 | 新手机 APP 登录 | 手机任务暂停；读取更换资格 |
| 不可更换/冷却中 | 返回其他功能 | 保持手机暂停，其他设备运行 |
| 可更换 | 完成新机校准 | 等待确认，原资产仍未下架 |
| 待确认 | 替换成功 | 原子变更绑定/槽位/执行权/次数；旧资产入仓 |
| 待确认 | 取消/失败 | 原绑定与资产不变，暂停状态不被误清除 |
| 已暂停且未成功替换 | 原绑定手机在暂停后主动重新登录认证 | 按最新绑定与在线条件恢复，领取新任务，不补暂停期收益 |
| 已替换 | 旧 APP 心跳/任务结果/旧页面提交 | 拒绝旧执行权与未确认迟到结果；停止前已确认结果按幂等规则结算 |

禁止把登录动作当成换机成功；禁止仅校准完成就记次数；禁止所有手机资产同时改名/改算力；禁止旧 APP 心跳自动抢回绑定；禁止通过 H5、换浏览器、改设备名、清存储或时钟回拨绕过策略。

**⑤ 交互原型（4 态）**

- 默认态：展示当前手机和已绑定手机名称，换机说明、资格与下一步；更换必须有确认，说明旧手机将下架。
- 空状态：无绑定明确引导校准；无空槽明确引导先管理激活槽。
- 加载态：核验身份/策略、校准、提交分别显示当前步骤，防止重复提交。
- 报错态：禁换、冷却、身份待核验、网络失败、校准失败、状态冲突分别展示原因；允许重试、取消或继续非手机功能。

**⑥ 点击流矩阵**

| 触发 | 目标 | 结果 |
|---|---|---|
| 未绑定 APP 登录 | 当前手机校准 | 校准成功再确认激活 |
| 异机可换：开始校准 | 新手机校准 | 成功进入替换确认 |
| 确认替换 | 服务端原子操作 | 成功才改变绑定与槽位 |
| 取消/稍后处理 | APP 其他功能 | 不换机，不消耗额度，手机暂停 |
| 冷却后重试 | 刷新资格 | 显示最新结果 |
| 本机仓库手机：激活 | 槽位管理 | 本机且有空槽才成功 |
| 异机仓库手机：激活 | 当前页原因提示 | 不改变资产 |
| 提交超时：查询结果 | 原请求读回 | 已成功直接展示，未成功再安全重试 |

**⑦ 跨文档一致性**

登录收口、App 恢复守卫、校准页、激活槽、仓库与设备详情共用资格结果。同步前端 §4/§6/§12 与后台手机设备策略；本节是换机事务的唯一规则定义，运行状态引用 RUN1，不另造一套规则。

#### [FEAT-RUN1] H5 与 APP 会话、在线和任务联动

**① 用户故事**

作为同时打开 H5 与 APP 的账号持有人，我想网页登录不干扰仍在线的绑定手机，同时确保手机离线后不再接任务或生成虚假手机收益。

**② 验收（GWT）与异常路径**

- Given A 手机 APP 的绑定、激活、登录与在线资格均有效，When A 的 H5 或 B/电脑的 H5 登录，Then 都保留 A 的手机任务；H5 自己没有执行权。不能把“非同机”直接等同于停机。
- Given 仅 H5 登录且没有有效在线 APP，When 查询/领取任务，Then 手机停止新任务、有效算力归零，不计新增手机收益；已购设备保持原状。H5 不自动把暂停手机从槽位挪到仓库。
- 异常1：Given H5 不能证明与 APP 是同一设备，When H5 登录，Then 查询账号当前绑定 APP 的服务端执行状态；在线保留，已离线暂停，未知显示核验中并重试。不能把浏览器身份不同或一次查询失败当成已离线并永久撤销 APP。
- 异常2：Given 同机 APP 已退出、会话撤销或执行在线超时，When 任务调度检查，Then 手机停止；“H5 在同一手机打开”不能替代有效 APP 会话。网页登录这个事件本身不缩短已有 APP 在线宽限。
- 异常3：Given 异机 APP 登录已造成暂停或绑定已替换，When 旧 APP 继续发心跳，Then 不能自行清除暂停、不能再领任务、不能覆盖新状态；需按 APP1 重新认证/绑定检查。
- 异常4：Given 设备停止后恢复，When 收到新的有效 APP 执行状态，Then 从恢复时重新计时；双币收益、排行榜、实时算力与任务列表都不补算停止区间。
- 异常5：Given 页面退出/关闭、H5 多标签、APP 前后台切换，When 服务端失去有效心跳，Then 在统一期限后停止手机分配；逻辑必须由服务端定时/调度执行，不依赖某个网页仍开着。实际原生前后台运行能力必须真机证明。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填/默认 | 权威与约束 |
|---|---|---|---|
| appSession | sessionId、accountId、installationId、expiresAt、revokedAt | 有效 APP 会话必填 | H5 会话独立，不能刷新 APP 登录/执行期限 |
| phoneExecution | bindingVersion、assetId、onlineUntil、pauseReason | 激活手机必填 | 服务端产生；只接受绑定安装的有效证明和心跳 |
| pauseReason | offline / session-ended / device-change / identity-unverified / 原有运行原因 | 可空 | 是业务契约，页面展示自然语言；H5 不得覆盖 device-change |
| sameDeviceProof | 服务端确认的同机关联 | 可空 | 缺失不猜测。即使无法确认同机，查询原 APP 在线状态仍可得出保留/暂停结论 |

执行资格 = 绑定目标正确 ∧ 已激活 ∧ APP 会话有效 ∧ 执行在线有效 ∧ 无换机/身份阻断 ∧ 原有电量网络条件满足。H5 登录只触发查询/同步，不获得执行资格。生产端安装身份的持有证明方案需在实施前以真实原生能力选定，不以演示 UUID 替代。

**④ 状态机 + 禁止动作**

有执行资格 → 接任务；失去资格 → 停止接收且暂停计产；再次获得资格 → 从恢复时起接任务。H5 页面可处于“核验中”，该展示状态不改写服务端最后已确认状态；新任务调度仍必须有有效执行资格。历史已结算收益不倒扣，进行中任务按以下建议处理，随补充口径一起确认：

| 停止原因 | 尚未确认完成的旧任务 | 恢复动作 | 迟到结果 |
|---|---|---|---|
| 服务端确认离线/退出/会话撤销 | 取消，停止计产 | 重新满足资格后领取新任务 | 停止后才到达的未确认结果拒绝；停止前已确认结果可重试入账一次 |
| 异机 APP 登录暂停 | 取消 | 原绑定手机主动重新登录，或新机替换成功后领取新任务 | 同上；静默恢复/心跳不能解除暂停 |
| 成功替换导致旧绑定失效 | 取消且旧执行权永久失效 | 新手机用新绑定版本领取新任务 | 不接受旧版本未确认结果，不迁移旧任务到新机 |
| 原有短暂电量/网络中断，尚未判离线 | 依现有任务宽限暂停/取消 | 仅同一有效绑定可按原规则续跑 | 仍须会话、绑定版本和完成校验；不借宽限跨手机续跑 |

禁止浏览器写 APP 心跳；禁止 H5 登录把所有设备 `offline`；禁止低于 APP 基础在线收益的“网页保底收益”；禁止用旧绑定版本提交结果；禁止用网页登出连带注销 APP，除非明确操作既有“退出所有会话”。

**⑤ 交互原型（4 态）**

- 默认态：网页能力提示与真实设备卡片并存；APP 在线时网页显示“绑定手机 APP 正在运行”。
- 空状态：没有已激活手机时给 APP 激活引导。
- 加载态：执行状态核验中，不显示伪造的在线/收益增长。
- 报错态：状态读取失败可重试，离线则显示“请在绑定手机打开 APP”；换机暂停显示对应原因。

**⑥ 点击流矩阵**

| 触发 | 目标 | 结果 |
|---|---|---|
| H5 登录 | 查询绑定 APP 状态 | 保留在线任务或展示已暂停 |
| 手机运行提示 | 手机详情 | 查看原因与 APP 引导，无 H5 启动按钮 |
| 状态重试 | 服务端状态重读 | 不伪造心跳 |
| APP 回到前台 | 重新校验会话/绑定/执行 | 一般离线可按条件恢复；device-change 必须另行主动登录认证 |
| 打开已购设备 | 原有设备页 | 原有任务、收益与管理流程不变 |

**⑦ 跨文档一致性**

共用服务端执行状态供任务、结算、详情、仓库、主页和排行榜消费；现有 `h5BaseFactor` 不再参与手机收益。购买设备及电脑算力等其他类别保持其既有契约，不将手机规则扩散到其他业务。

#### [FEAT-OPS1] 后台手机换机策略

**① 用户故事**

作为有策略管理权限的运营人员，我想控制是否允许手机换绑及成功更换的最短间隔，以便在无需更新安装包的情况下调整规则。

**② 验收（GWT）与异常路径**

- Given 有权限且配置合法，When 确认保存允许换机与 N 天间隔，Then 产生新策略版本，下一次登录核验与替换提交立即读取新规则；刷新可读回。
- 异常1：Given 无权限、负数、非整数或超出存储边界，When 保存，Then 前后端拒绝，不改变旧规则；普通账号不能修改策略。
- 异常2：Given 保存超时或配置并发修改，When 重试，Then 查询版本并明确成功/冲突状态，不显示假成功；原有效配置继续适用。
- 异常3：Given 校准期间运营关闭换机或提高间隔，When 提交换机，Then 按新版本拒绝；不先把原手机下架、不扣额度。
- 异常4：Given 配置缺失/读取失败且无可信有效版本，When 请求换机，Then 暂不允许换机并提供重试；不影响已经合法运行的本机手机及购买设备。

**③ 数据字典 + 生成规则**

| 字段 | 类型 | 必填/默认 | 权威与约束 |
|---|---|---|---|
| phoneBinding.allowReplacement | boolean | 必填，默认待确认 | 后台可配置 |
| phoneBinding.minReplacementIntervalDays | 非负整数 | 必填，默认待确认 | 0 为不设间隔；禁止负数/NaN；换算毫秒不溢出 |
| policyVersion | 单调版本 | 服务端生成 | 原子保存，登录与提交同源读取 |
| nextAllowedAt | 毫秒时间戳 | 服务端计算 | max(首绑或最近换机时间 + 间隔, 当前资格约束)；关闭换机时不承诺日期解锁 |
| audit | 操作者、时间、原因、前后值、结果 | 策略更改必填 | 复用后台现有权限/确认/审计机制 |

最小配置只提供开关与间隔，不新增个人白名单、付费解锁换机、强制解绑或管理员代替换机等未要求功能。

**④ 状态机 + 禁止动作**

有效旧策略 → 编辑草稿 → 校验/确认 → 保存新版本；失败留在草稿并保留旧版本。禁止前端先改本地策略就宣称全平台生效；禁止把策略关闭解释为把所有同机手机停机。

**⑤ 交互原型（4 态）**

- 默认态：开关、数字间隔与作用说明；关闭时说明不允许更换，间隔仍保留。
- 空状态：尚无策略显示待配置；不静默不限次。
- 加载态：读取或保存中锁住重复提交。
- 报错态：非法输入就地指出，网络失败可重试，版本冲突先重载后编辑。

**⑥ 点击流矩阵**

| 触发 | 目标 | 结果 |
|---|---|---|
| 修改允许换机/间隔 | 当前草稿 | 未保存不影响线上 |
| 保存 | 确认与原因 | 校验、权限、审计后生效 |
| 取消 | 原配置 | 丢弃草稿 |
| 重载/重试 | 当前服务端版本 | 明确冲突/成功，不覆盖他人改动 |

**⑦ 跨文档一致性**

`admin-ops` UI、`nexion-backend` 持久化与前端只读策略使用同一版本。现有 E6 基础系数大于 0 的规则不能与“手机停止即零产出”冲突：退役其手机消费，其他适用业务另行保留，不全局清零配置。
