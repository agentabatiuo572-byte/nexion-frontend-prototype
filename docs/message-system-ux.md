# 消息中心交互约定

设计参考：[主界面 V3](design/message-center-20261002-v3.png)、[滚动状态](design/message-center-20261002-scroll.png)、[消息相关子页面](design/message-subpages-20261003.png)、[工单消息记录](design/ticket-message-timeline-20261003.png)。图中示例记录和数字不构成业务事实，通知与服务数据必须严格分区；滚动状态图中混入的服务示例不予还原。

- 配色遵循 nexion-design 与项目现有 tokens：深色黑底、荧光绿少量强调；浅色暖白底、蓝色强调。所有交互按钮复用 Liquid Glass，内容行保持扁平。
- 到达页面顶部时显示标题、总未读、通知/服务一级分区及当前分区末级筛选。
- 一级分区显示完整未读数（含零）；末级分类用圆点表达存在未读。通知按服务端全量类型摘要分类，服务按可见人工会话及工单的完整列表统计，不用第一页代替全量。
- “清空已读”在总未读同行右侧，保留确认和至少 44px 点击区域；随标题收起后退出键盘焦点序列。清空仅影响通知已读记录，“全部已读”仍可独立使用。
- 明显向上滑动浏览后收起大标题和一级分区，末级筛选保留在顶部；紧凑标题保留当前分区上下文。
- 明显向下回滑恢复一级分区，不要求先回到列表顶部；回到顶部再恢复大标题。切分区时重置相应导航状态，不复用另一分区过期滚动位置。
- 标题与一级分区保持挂载，按内容实测高度展开或折叠；列表末尾补足收起的高度，与顶部共用 260ms 高度过渡，使可滚动空间连续变化。语言、未读文案或窗口尺寸变化后重新测量，不能靠固定高度裁切较长内容。
- 真实滚轮、触摸或键盘输入可在过渡中改变方向；布局变化产生的滚动事件不作为主动回滑。快速反向操作仍从当前位置连续过渡，不能出现一次跳满高度、列表回弹或末尾内容被遮挡。
- 轻微手指抖动不反复展开收起；滚动位置不能因动画来回跳。键盘聚焦的一级控件不在操作中被收起。减少动画设置下取消过渡，但保持功能相同。
- 所有铃铛和 Me 消息入口直接进入全屏消息中心，无侧边抽屉或遮罩；保留当前分区，入口可指定初始分区。在中心再次点铃铛不叠加页面，返回恢复来源页面；冷启动进入时返回 Me。分区切换/查看总览不标记人工或工单已读，通知设置保留在全屏页内。

- 人工浮标与客服渠道的“在线会话”统一进入服务分区；点会话行进入现有全屏聊天，返回保留服务分区。“会话管理”仍可新建会话和管理历史，不作为独立人工快捷入口。
- 会话管理、聊天、客服渠道与工单列表/创建/详情沿用同一组字体、间距、选中态和焦点反馈。返回、筛选、分类及提交等交互控件使用 Liquid Glass；消息正文、说明、列表行和静态统计保持扁平，避免内容卡片再套卡片。每个页面保留明确的返回、加载、空态和失败重试出口。
- 工单创建页先读取服务端建单能力，等待或失败时禁用提交并保留当前输入。当前正式合同为 `mode: BASIC`，仅表示既有基础建单 POST 已交付，不表示某份草稿已获准，也不返回 `allowed` 或增强阈值；标题、正文、分类、身份、生产环境与原号幂等仍由原 POST 校验。冷却、窗口数量、活动工单上限与语义重复判断四项增强保持 DEFERRED，未取得产品定值与正式交付前不开启；若服务端以后明确返回完整增强策略，受限时沿用简短原因与重试或“查看已有工单”入口。提交过程中显示处理中并防止连点；规则变化以最新服务端结果为准，回复与重开继续按工单状态处理。
- 工单详情沿用服务端消息顺序，按消息日期分组；长记录可展开与收起，始终保留完整原文。历史作者仅采用消息的公开署名，缺失时使用当前语言的客服称谓，不猜测原作者。折叠状态按账号、工单和消息隔离；回复、历史加载和已读规则保持原契约。
- 工单详情标题无背景，按屏幕水平居中；圆形返回与紧凑的纯文字“查看工单列表”动作位于同一导航行，该页不重复放置消息入口。新建工单和其他子页保留各自现有导航。

验收：顶部→向上浏览→继续阅读→过渡中反向滑动→明显回滑→切换服务→打开会话/工单→返回→刷新；覆盖短列表、长列表、空列表、列表末尾、加载失败、320px、中/英/越、浅/深主题、键盘和减少动画设置。工单另验证策略读取失败、暂时受限、重复内容、提交失败保留输入及成功进入详情。
