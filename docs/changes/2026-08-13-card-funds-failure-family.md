# 卡:资金操作失败后「没人补、也不告诉用户」—— 全站族,按族治不逐个补

- **状态**:🅿 待规格(主人 2026-08-13 拍板立卡)
- **来源**:z6 的 R1 独立审计做同形全扫时发现,**10 条 P0 全部是范围外的既有缺陷**。
- 🔴 **治法要求(主人拍板时明确)**:**按族治,不逐个打补丁**。
  逐个补丁必然复发 —— 这一族的成因是结构性的(返回值可以被静默丢弃),不是 10 个独立疏忽。

## 1. 族的定义

资金类操作(改余额 / 写账单 / 铸设备 / 消费资格)**返回了失败,而调用方丢弃了这个返回值**,
于是:钱动了账没记、账记了钱没动、资格消费了奖没发 —— 且**没有任何一处会在之后发现并补上**,
用户也得不到告知。

**扫描基数**(审计逐个读过 ±40 行,不是 grep 计数):
资金原语真实调用点 **55 处**;`persistAccountSnapshot` **27 处,其中 15 处丢弃返回值**;
各 store 的 claim/redeem/settle/mark 类 action **60 处**。

## 2. 已确认的 10 条(P0,全部范围外既有)

| # | 位置 | 现象 |
|---|---|---|
| 1 | 入金三轨(链上 / 银行 / 卡) | 收据写入返回值被丢弃 ⇒ 钱已入账、分录永久缺失;对账循环只遍历提现,**没有入金格** |
| 2 | 购买 / 组合 | 收据返回值丢弃;组合还无条件弹成功并跳转 |
| 3 | 质押开仓冲正 | 冲正返回值丢弃 ⇒ 退款可能失败而页面照弹「开仓失败」(孪生点 `wallet-repurchase` 接了) |
| 4 | 以旧换新「保留并购买」 | 设备已落盘,付款失败的回滚**只改内存不落盘** ⇒ 重开白送一台设备 |
| 5 | 收益里程碑 | 用非幂等写入 + 标记落盘失败静默 ⇒ 重开二次发钱 |
| 6 | 每日签到 / 连签(2 处) | **先消费资格后发钱**,发钱失败即永久归零 |
| 7 | 质押平仓 / 领取 | 先 CAS 关仓后付款,失败只留一条 toast |
| 8 | 幸运转盘 | 先扣票后发奖;且 ref 带时间戳 = **假幂等**(判重永不命中) |
| 9 | 传统换绑 $1 返还 | 失败只 `console.error`,而迁移标记**无条件消费** ⇒ 该分支永不再进 |
| 10 | `settle()` 收益入账 | 落盘返回值被丢弃(同文件其余 12 个原语都接了) |

## 3. 顺带纠正一句错注释

`src/lib/withdrawal-bill-drafts.ts:13` 写着「资金分录里**只有这一族**没有自愈路径」——
**不成立**,入金与购买同样没有。z6 当初正是照着这句话把提现当孤例来修的。
治族时一并改掉,否则下一个人还会重蹈。

## 4. 建议治法:一道机器门 + 一条不变量

**不变量**:资金原语与落盘函数的返回值**不得被丢弃**;调用方必须二选一 ——
① 失败时回滚并如实告知用户;② 把待办交给一个会重试的地方(对账循环 / 待对账队列)。

**机器门方向**:
- 判据取**磁盘真实实体**:从 store 导出面解析出「资金原语」名单(不手写清单,防漏),
  再扫全站调用点,凡处在**语句位**(返回值未被 `if` / 赋值 / `return` / `&&` 消费)的一律判红。
- 白名单必须写理由,且理由要能被红测证伪。
- 🔴 门必须**双向红测**:摘掉任一处的返回值消费必红;加回必绿。

**配套**:`reportStuckFunds` 那条待对账队列目前**全仓无产品消费者**(只有自检脚本读),
给用户的「记下这个交易号找客服」实际指向空。治族时要么接上产品面,要么改口径。
