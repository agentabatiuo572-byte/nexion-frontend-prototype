## 🔴 结构性判定:试用时间边界 = 一族,不是四个 bug

审计 P0(convert 越界)+ 审计 P1(累计上限用当前配置)+ 审计 P1(finishedAt 记成 now)+ 走查 P1(存量卡时代行永久卡 grace)——**四条同型**,触发「同型复发 → 强制结构反思」。

**共同根因(回源坐实,2026-08-03)**:`src/store/free-trial.ts` 的时间边界判定
1. **只推进一格**:`poll()` L239-245 在 active→grace 后 `return`,同一次调用不级联到 ended;
2. **各消费者独立推导**:`convert()` L215 只看内存态、完全不比对 `mockServerNow()` 与 `graceEndsAt`;`liveShadowUSD/NEX` L265/L276 与 `poll()` L238 各自用 **当前** `cfg.trialDays` 当上限,而不是用户 `start()` 时冻结的窗口(`expiresAt − startedAt`);
3. **空边界静默失效**:L245 要求 `graceEndsAt !== null` 才允许 grace→ended,存量卡时代行(旧 schema 无该字段)因此永久停在 grace。

**根治方案(一条不变量,禁止四处打补丁)**:抽单一纯函数 `resolveTrialAt(row, now, cfg)`,一次性级联全部边界、上限取用户冻结窗口、终态时间取**真实越过的边界**而非 now、空边界在迁移期就地补齐(fail-closed:绝不留永久敞口)。`poll()` / `convert()` / `eligibility()` / 影子累计**全部**改调它。配套机器门:哨兵断言 convert 走 resolver + 自检脚本固定靶(离线跨 grace 后转化必拒、配置改动不影响存量窗口、finishedAt=边界值、空边界不卡死)。
