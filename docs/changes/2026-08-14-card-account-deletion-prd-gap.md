## 为什么这条不能当成「补个端点条目」了事

PRD 没写,等于**下面这些没有任何人拍过板**,而它们每一条都会真实影响用户的钱和数据:

| 必须定的问题 | 不定会怎样 |
|---|---|
| 注销时**账上余额怎么办**? | 用户带着余额点了注销 —— 退给谁、退到哪、还是直接没收?没定 = 客服现场编 |
| **在途提现单 / 未完成订单**怎么办? | 申请单进 `COMPLETED` 时链上还没确认,钱可能卡在半路 |
| **持仓设备 / 质押中的本金**怎么办? | 锁仓未到期就注销,是强制赎回还是拒绝注销? |
| `BLOCKED` 的**判定条件**是什么? | 状态机里有这个态,但没人定义什么情况下会 BLOCKED、用户怎么解 |
| 注销后**多久内可恢复**?数据留多久? | 这是合规硬要求(数据留存期),不是产品可选项 |
| **推荐关系**怎么处理? | PRD §8 说「注销的账户会被移除」计数,但上级的历史佣金怎么算没写 |

⚠️ 最后一条尤其要注意:**PRD 里唯一提到「注销」的地方是团队计数那句**
(§8 直推人数「降级或注销的账户会被移除」)——也就是说 PRD **假设了注销存在**,
却从来没有定义过它。这比完全没提更危险:读者会以为它已经被规格覆盖了。
