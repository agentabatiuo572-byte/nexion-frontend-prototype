# 资金 ⊗ 收据不变量 — 红测记录(2026-08-04 · R4)

被测门:`scripts/selfcheck-money-receipt.mjs`(已焊进 `scripts/verify.sh` 的 `money_receipt_gate`)。

## 一句话:这一族是什么

落盘失败在这一层是**静默**的 —— `account-cloud` 写不进去只是 `persisted:false`,`bills.add`
写不进去只是 `return null`,**两者都不抛异常**;而调用方一律按「一定成功」继续铸货、写账单、
弹成功提示。四处同型:

| 出处 | 症状 |
|---|---|
| `src/store/app.ts` 四个资金原语 | 丢弃 persist 结果 → 内存改了、磁盘没写成,刷新即回退 |
| `src/components/genesis/purchase-sheet.vue` | 已扣近 $15k、已铸席位、弹「购买成功」,账单页查无此单 |
| `src/pages/store/checkout.vue` | 跨 store 动钱后 `bills.add` 返回值被忽略 |
| `src/pages/me/wallet-repurchase.vue` | `debit → stake → bills.add` 无回滚无失败检测 |
| `src/pages/me/wallet-exchange.vue`(追加) | 一进一出两条分录,两处返回值都没人接 |

## 根治:一条不变量 + 一个收口点

**不变量**:任何资金变更都必须与它的收据**同生共死** —— 要么都落盘,要么资金被精确还原
(含 `withdrawableUsdt`),并且调用方一定拿到结果、用户一定看到提示。

**机制**:`src/lib/money-receipt.ts`。**收据即指令** —— 资金动作由 draft 的 `amount` 符号 +
`symbol` 派生,所以经这条路**不写收据就动不了钱**。这才是「一条收全族」,不是四个补丁。

**多腿交易的设计裁决(兑换一进一出)**:两条分录**一次落盘**(`bills.addMany` 单次 persist)。
因此「第一条落了、第二条失败,而钱两边都动了」这个中间态**根本不存在**:
- 不需要「删掉第一条」—— 复式账本里已落盘的分录不改写,而且它压根没落盘;
- 也不需要「补一条反向冲正分录」—— 冲正的前提是「已成事实」,这里没有事实可冲,补出来的
  两条只是账本噪声。

## 方法与硬规则

- 行为断言 **esbuild 载真 store + 真收口点跑真代码**(不抄判据副本);pinia stub 复刻两条真
  语义:一个 id 一个实例 + **自动解包 ref**(缺后者时 `app.user.usdtBalance` 恒 `undefined`,
  判据会静默走错分支而全绿 —— 第一版就踩到,已修)。
- 假 uni storage 可**按 key + 第 N 次写**定点注入失败,并记录写盘次数(「两条分录一次落盘」
  只有数写入次数才证得出来)。
- **逐个隔离**:一次只破坏一条合取项。
- 备份/还原**只用 `cp`**,禁 `git checkout`(工作树里有并发 agent 的未提交改动)。
- **注入自证**:锚点必须恰好命中 1 次、落盘内容必须真的变了,否则立即终止、红测作废。
  (第一版锚点用 LF、源文件是 CRLF → 命中 0 次,被这条规则当场拦下。)
- 还原后 **sha256 逐字节相同**,并复跑到全绿。

## 结果

基线:`59 pass / 0 fail`。15 条注入,**每条都让对应判据变红、exit≠0、还原后逐字节相同**;
全部还原后复跑 `59 pass / 0 fail`。

| # | 靶 | 注入的破坏 | 变红的判据 |
|---|---|---|---|
| R1 | ① | `debitBalance` 落盘失败不回滚(退回原实现) | ① debitBalance 返回 false / 内存不脏 |
| R2 | ① | `creditBalance` 落盘失败不回滚 | ① creditBalance 返回 false / 内存不脏 |
| R3 | ① | `debitNex` 落盘失败不回滚 | ① debitNex 返回 false / 内存不脏 |
| R4 | ① | `creditNex` 落盘失败不回滚 | ① creditNex 返回 false / 内存不脏 |
| R5 | ② | 收据写失败后不回滚资金(复现本族病症) | ② 资金被整笔还原 |
| R6 | ② | 收据写失败后不提示(静默吞掉) | ② 用户看得到失败提示 |
| R7 | ② | 收据写失败仍返回成功 | ② 收口点报失败(`outcome=ok`) |
| R8 | ③ | 冲正只还总余额、不还 `withdrawableUsdt` | ③ 冲正后可提额度恢复到扣款前 |
| R9 | ④ | 成功路径被改坏(扣款少扣一分) | ④ 成功路径金额与舍入不变 |

| R11 | ⑥ | 新增一处裸 `bills` 写入 | ⑥ 裸调 bills 写入不许新增 |
| R12 | 哨兵自身 | 把扫描判据打瞎(匹配不到任何东西) | ⑥ 扫描器没有空转(`total=0`) |
| R13 | ⑦ | 两条分录改成分两次落盘 | ⑦ 两条分录一次落盘(实测「写了 2 次」) |
| R14 | ⑦ | 扣款腿的**合计**预检被摘掉 | ⑦ 合计预检(单腿够 / 合计不够) |
| R15 | ⑦ | 某一腿落盘失败后不还原已动的腿 | ⑦ 第二腿落盘失败 → 第一腿也退回 |

R12 是**对哨兵本身**的红测:破坏判据(而不是破坏实现)也必须 BLOCK —— 「判据失效 = 空集
全过」是这类扫描器最常见的假绿来源,故门里带一条活体证明(`total > 0 && files > 100`)。

R8 顺带证实了退款语义不对称的真实形态:退化成裸 `creditBalance` 后**总余额看着完全还原**,
只有 `withdrawableUsdt` 被悄悄压低(实测停在 8500 而非 10000)。任何测这条的桩,`debitBalance`
必须照 app.ts 同款把可提额 clamp 到扣款后余额,否则裸 credit 与 `restoreTo` 在门下长得一模一样。

## 仍在台账上的迁移欠账

收口点已就位,但本轮**文件边界外**还有 15 个文件在裸调 `bills` 写入(全部与资金动作配对,
同族)。门里冻了一份 `LEDGER`(键是文件不是行号 —— 行号会被并发编辑冲掉),**只许减不许增**:

本身不是回归)。
