# 包 z6 · 失败提现退还已烧 NEX —— 结构性反思 + 红测台账(2026-08-11)

## 0. 这个包修的是什么

失败提现退还已烧 NEX 的**账单冲正分录**(`+N NEX`)在**任何真实配置下都不可达**。

回源确认的链条(不是猜的):

| 环 | 事实 |
|---|---|
| 判据 | `App.vue` 的冲正行判据 = 本地幂等键 `appliedRewardKeys["refund-nex:<id>"]` |
| 唯一写入点 | `app.ts` 的 `refundFailedWithdrawals` → `creditRewardBucketOnce` |
| remote 模式 | `creditRewardBucketInternal` **第一行**就是 `if (remoteApiEnabled) return false` → 键永不被写 |
| mock 模式 | `createMockModeApiClient` 让每个请求 reject → **建不出提现单** |

两头落空。**根因不是「缺服务端契约」**(卡上原话),而是「写证据的那个函数在唯一会产生提现单的模式里被整体早退」——
就算服务端有了契约、客户端也照着调,那一行照样挡掉。所以修法是**换证据源**,不是补契约调用。

修法:判据改锚服务端字段 `nexRefunded`(契约 FEAT-WD01 §4.6),冲正分录从 `App.vue` 并入
`lib/withdrawal-bill-drafts`(那里本就是「一笔提现该有哪几条分录」的唯一构造处),
自愈 / 按方向判重 / 跨账号补记三件事全部继承既有机制,`App.vue` 净删 38 行。

## 1. 🔴 结构性反思(独立审计同型复发 ≥2,强制)

五份独立审计回来后,**同一个根因出现了 4 次**,触发强制反思:

| # | 实例 | 谁发现的 |
|---|---|---|
| 1 | 字段只在**消费点**设防;落盘合并层(`mergeWithdrawals` 整对象按状态 rank 取胜、平局留旧份)会把它整份丢掉 —— 四个失败终态 rank 相同,「状态没变、只补了退款事实」这种更新**必被吃掉** | 契约解析面 |
| 2 | 机器门只覆盖「分录→账本」后半截;`App.vue` 决定**要不要补**的那两行被门里自己重写的调用绕过 —— 变异 `every→some` 后缺陷原样复发而三道门全绿 | 机器门面 |
| 3 | 机器门把 `withdrawalApi` 整个桩掉,两条自称「穿过 parseSubmission」的断言**是空转**(桩路径下缺字段得 `undefined`,真解析得 `0`) | 横切红队 |
| 4 | 我在注释 / 规格 / 交接文档三处断言「回查端点复用 `toCanonicalWithdrawal`,字段自然跟着走」——回查端点**已经**在并行包 z7 写完,有自己的响应类型与解析器,只回 5 个字段,**不带该字段** | 横切红队 |

### 共同根因(一条)

> **对一条跨层路径,我只检查/只设防了「我当时正在看的那一层」,并把「其余各层会配合」当成事实写进注释、规格与交接文档。**

这个字段实际要穿过 **4 层**:解析 → 落盘合并 → 对账决定 → 分录构造。
我只在第 4 层设了判据,门也只测第 4 层。前三层里有两层会**静默吃掉证据**,而所有静态门全绿 ——
与本包要修的缺陷**同形**(证据在半路消失,门看不见)。

### 四问

| 问 | 结论 |
|---|---|
| ① 方向性偏差? | **否**。「服务端权威 + 客户端只消费证据」是对的路线,z4 R3 已否掉「客户端自己推」那条(凭空宣布无证据的退款) |
| ② 结构性错误? | **是**。任何「新增跨层字段」都会重犯,除非有一条不变量把 4 层绑在一起 |
| ③ 同型根因 → 一条根治(禁逐个打补丁) | 不变量:**冲正判据依赖的字段,必须在它经过的每一层都被证明存活**;门必须**从服务端回执一路跑到账本行**,中间不许用重写的调用绕过任何一层 |
| ④ 层级归位 | 机器可测 → 门(⑧⑨⑩⑪ 四格,见下);跨包 → ⑪ 条件式判据;跨任务心智 → memory |

**结论:确有结构问题 → 已先改结构再收尾**(不是在原结构上逐条打补丁)。

## 2. 修了什么(逐层)

| 层 | 改动 | 文件 |
|---|---|---|
| 解析 | 只认真正的 JSON **整数**;`true`/`"3"`/`[3]`/小数/负数一律 0。**不复用共用 `number()`**(它内部 `Number()` 强转,`true→1`) | `api/withdrawal-api.ts` |
| 落盘合并 | `nexRefunded` **按取大单独合并**,不随整对象被 rank 平局淘汰;单调不减 | `store/account-cloud.ts` |
| 对账决定 | 未改逻辑,但门改为**抠真源码整段执行**,把「要不要补」纳入射程 | `App.vue`(不变)/ 门 |
| 分录构造 | 判据 = `wd.nexRefunded`;金额取它本身不取 `nexBurned`;`> nexBurned` 整条不写(不夹取) | `lib/withdrawal-bill-drafts.ts` |
| mock 两条腿同生共死 | 本地退款腿成功后**同步写下 `nexRefunded` 证据**,否则 mock 下「钱包退了、账单没记」 | `store/app.ts` |

## 4. 已知缺口(**不当作已修**)

1. 🔴 **线上仍不可达**:提现单提交后无状态回查入口;而并行包 z7 的回查契约**不带 `nexRefunded`**。
   两包按现状合并,这条冲正一次都不会触发。已登记 HANDOFF **U-9**,并焊 ⑪ 条件式判据
   (本仓一旦出现回查面而不带该字段 → 当场判红)。
2. **冲正行的日期盖的是提现提交时刻**,不是退款时刻;账单页按月分组,「7 月提交、8 月退还」会显示成 7 月的事。
   根治需要契约补 `nexRefundedAt` + 账单落账支持逐分录时间戳(动的是共用资金原语)——已写进规格 §4.6 的后端待办,
   实现独立成卡,不在本包硬塞。
3. **部分/追加退还不支持**:账单判重键不含金额,先落 `+1` 之后服务端改口发 `3` 会被整条判重丢弃。
   规格 §4.6 已从「将来改策略不用改客户端」**改成**「当前必须全额且一次性;要放开必须同批改判重键并配红测」。

## 5. 编排上的自我检讨

派审计单时,我把「机器门自身」那份**要求它做变异测试**,却和另外四个只读 agent **并行**跑 ——
于是被审文件在别人读的过程中被改了又还原。后果:一份报告报了一次「不可复现的偶发判红」,
事后我连跑 8 次全绿,失败签名 `[-3,3]` 恰好等于当时另一个 agent 的 M2 变异 —— 是**我编排造成的幻影**,不是真缺陷。
**规矩**:要变异的 agent 必须与只读 agent 串行,或安排在全部只读 agent 收工之后。
