**判据的第一性原理**(决定什么算违例):
- 真灰(`r=g=b`,如 `#000/#fff/#0F0F0F`)= 主题无关的通用光影 → **不是语义色副本**,排除,否则遮罩/投影洪水般假阳性。
- 只钉**亮值 ≠ 暗值**的 token → 单主题 token(如 `--v5-quest-violet`)的副本不会失配,不入机器门,避免噪声。
- 比 **RGB 三元组、忽略 alpha** → 变透明度副本同样必失配。

**真问题**:亮主题下 V3 = **蓝字 + 柠檬底**(`--v5-brand@light` 是电光蓝)、V5 = **青字 + 紫底**(`--v5-tech-cyan@light` 是青)。

| 方案 | 做法 | 后果 |

| **(a) 整族跟随主题** | 13 档 bg/ring/text 全部由 token 派生 | 亮主题下 V3 徽章是蓝的、暗主题是柠檬的 —— **同一军衔两个主题两种颜色**,军衔作为身份标识不稳定;且 4/6/8/9 档的「同族更亮变体」需要发明派生值 |

### 4.3 🔴 `scripts/theme-constant-gate.mjs` —— 运行时正交门(本批最重要的机制产出)

**为什么必须新建一道门,而不是继续加强静态哨兵**:
本批**同一个根因连踩三次** —— ①按颜色值全等比 token,漏掉全部变 alpha 副本 ②按值 grep 遮罩,20 个只捞到 9 个
③按值 grep 网格线,4 个只捞到 2 个。三次都是**用「值」去找「扮演某角色的东西」**。
静态哨兵的天花板就在这里:它只能钉「我已经想到的写法」,想不到的写法(别的值、别的语法、拼接出的字符串)
天然在射程外 —— 独立验收把这类命名为 **N5 假阴性**,并指出「本次最严重的 3 个用户可见缺陷全在这一类」。

**换正交维度**:不问源码怎么写,只问**渲染出来跟不跟主题**。
双主题各渲染一遍,取每个可见元素的 `color / backgroundColor / borderTopColor / fill / backgroundImage`,
两主题 computed **完全相同**的有色值即嫌疑 —— 不管它在源码里长什么样。

两道减噪让它可用(全站仅 8 条指纹,噪声极低):
① 值等于「两主题同值 token」→ 放行(这类恒定是 token 体系自己规定的,如 `--v5-on-brand-2` 双主题都是 `#0A0A0A`);
② 真灰 `r=g=b` → 放行(通用光影)。存量走棘轮基线 `docs/THEME-CONSTANT-BASELINE.json`,门只拦**新增**。

**它当场证明了自己的价值**:独立复现了验收 agent 手工找到的创世金 2.08:1 与 quest 紫,
并**额外**捞出待拍板 2 的遗留品牌绿 rgba 形式 —— 而我修好的 4 处网格线一条都没出现(反证修对了)。
自检 18/18(含 `backgroundImage` 整串比对的阳性/阴性红测)。
