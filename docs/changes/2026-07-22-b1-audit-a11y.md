# B1 设计审查 · 无障碍 + 动效镜头(Nexion-uniapp 五 tab 主链路)

**本页判定目标 = WCAG 2.2 AA 对比度 4.5:1(大字 3:1)/ Focus `2px var(--v5-brand)` + 2px offset / 触控 44×44 / 拖拽必有点击替代 / 状态不只靠色 / 动效时长落《08》§2 档位表 / `prefers-reduced-motion` 全量降级 / 同屏大数字 tick ≤2**
**来源:`UI/规范/07-无障碍规范.md` §1–§7 明写 + `UI/规范/08-动效规范.md` §1–§5 明写。**
**推断项(规范未明写,按 WCAG 2.2 标准补齐):① "大字" = ≥24px,或 ≥18.66px 且字重 ≥700;② `--v5-ink-4` 在 tokens.css 注释里定义为 "quaternary / disabled",据此推断它不应承载正文/标签文字;③ 非文字图形(状态点、图标)按 1.4.11 的 3:1 判,不按 4.5:1 判。**

补充(非 a11y,顺手):`src/pages/index/index.vue` `.home-task-carousel__swiper { transition: height 240ms ... }` 动的是 **layout 属性 height**,不是 compositor 友好属性。P3。

### 4.2 Tick(§5)

**6.2 秒窗口 × 5 tab × 双主题实测:字号 ≥18px 的文字节点变化数 = 0。**
→「同屏最多 2 个大数字同时 tick」**通过**(静置状态下根本没有大数字在 tick,包括 me 页 48px 的 `$24,856` 和 store 22px 的 `$7.00`)。

首页 6 秒内有 10–15 个小字号节点变化,逐条核过:
- 6 条 12.5px 是 **live-feed 整行轮转**(第 N 行接管第 N−1 行的内容),不是每行各自 tick 数字;
- 5 条 10.5px 是同一 feed 的时间戳列跟着轮转;
- 1 条 16px 是倒计时钟;2 条 11.5px 是 `+$0.xxx` 增量。
→ §5「长列表**不**每行都 tick」**通过**(是列表整体轮转,不是逐行数字滚动)。

### 5.3 一处**该补的硬化**(不是 bug,是防未来踩坑)

兜底照抄了《08》§3 的片段,**没有重置 `animation-delay` / `transition-delay`**。当前唯一命中的是 `.ms-medal`(`ms-medal-pop`,`delay 0.1s` + `fill: both`,出现在 earn/store/team/me):reduce 下它会在 `from` 关键帧(缩小+透明)停 100ms 再瞬间到位 —— 100ms 感知不到,**现在不构成问题**。但只要以后有人写一条 `animation-delay: 0.6s` + `fill: both` 的错位入场,reduce 用户就会看到内容"消失 0.6 秒再闪现"。

建议在 catch-all 里补两行(社区通行版本):

```css
animation-delay: -1ms !important;
transition-delay: 0s !important;
```

**结论一句话:全局兜底真生效、真全覆盖、零功能副作用;唯一缺口是 delay 未重置,属于防御性硬化而非现存缺陷。**

## ⑥ 教条 / 存疑 —— 明确判为"不是问题"或"证据不足"

写在这里的每一条,都是我先怀疑、再回源验证后**撤回**的,列出来是为了防止别人重新"修"它。

1. **代金券 CTA「领取」不是低对比度。** 像素环采样一度给出 1.14–1.61:1,回源核对发现:该 pill 的盒子紧贴文字,外圈 3px 环采到的是**按钮外面的卡片底**,不是按钮自己的填充。CSS 真值 = `--v5-on-brand #0A0A0A` on `--v5-brand #9EDC1D` = **11.98:1**(暗)/ `#FFFFFF` on `#0E48E6` = **6.80:1**(亮),**双主题都远超 AA**。同理被撤回的还有暗主题角标「4」(实为 `#0A0A0A` on `#FF7A3D` = 7.64:1)。
2. **暗主题「E」头像字符不达标 —— 撤回。** CSS 派生法给 3.37:1,但实景像素显示它所在盒 92% 是 `#141414`,真值 `#8E72FF` on `#141414` = **5.26:1 通过**。CSS 派生在多层半透明祖先上会挑错面,凡与像素法冲突的,以像素法为准。
3. **`outline: none` 不是滥用。** 全仓两处,`index.vue:327` 与紧邻的 `:focus-visible` 成对出现;`register/success.vue:190` 作用于 `tabindex="-1"` 的程序化聚焦标题(路由完成后 `.focus()` 让读屏播报新页标题),给这类元素去掉焦点环是**正确做法**,加环反而是视觉噪声。
4. **7px 状态点、SVG 图标不按 4.5:1 判。** 它们是非文字图形,适用 1.4.11 的 3:1;实测全部达标。首页设备行的问题是"只用颜色编码",不是对比度不够——修法是加文字/图标,不是加深颜色。
5. **无限 `spin` 加载环在 reduce 下被冻成静止图标 —— 不是缺陷。** 《08》§3 明确要求关闭连续动画;WCAG 也是这个意图。若担心"用户看不出在加载",那属于加载反馈四档(§1)的设计题,不属于本次 reduced-motion 改动的回归。
6. **`--v5-ink-4` on `--v5-bg` 的 4.42:1(暗)与 `--v5-ink-3` on `--v5-bg` 的 4.47:1(亮)**:分别只差 0.08 / 0.03,肉眼与 4.5:1 无差别。**技术上算失败,已列表,但定为 P2/P3**,不建议为它们单独开工单;跟着 1.3 的 token 层修复一起被覆盖即可。
7. **里程碑庆祝浮层在 earn/store/team/me 自动弹出并自动消失** —— 这触及 WCAG 2.2.4(Interruptions,AAA)与 2.2.1(Timing Adjustable),但**两份规范都没写这条**,且它是有意的产品行为(点任意处可立即关闭)。**只作为观察记录,不计入本次判定**,交产品判断。
8. **`active:*` 类作为"可点元素"的代理指标有误差** —— 可能漏算不用 tap 反馈类的可点元素。所以 B4 的结论我不单靠它,而是以 **Tab 遍历实测计数**为主证据、类统计为旁证,两者结论一致才写进 P1。
9. **home 页 6 秒内 10–15 个文字节点变化** 一度像是"长列表每行 tick"违例,逐条读过内容后确认是 **feed 整行轮转**(第 N 行接管第 N−1 行的字符串),不是每行数字各自滚动。**撤回。**
10. **未能取证的两处**:store「云端 · 分布式」(CSS 派生 2.55:1,亮主题 `#8E72FF` on `#DCDCDC`)与 store 徽标「M」—— 定向复测时元素未命中(文本被拆成多节点/需要特定滚动位)。**这两条仅有 CSS 派生单一来源,未经像素复核,标记为待验,不计入 P0/P1。**
