## 四问

### ① 根本路线选错没?

**没有。** 「计数从提现单列表现算、不另存计数器」这条路线本身是对的:它消灭了
「两份状态必然掉队」这个原始病因,8 份报告里没有一份质疑这条路线,
`countWithdrawalsOnPlatformDay` 的判定正确性也被逐条代入验过(P0=0)。

**但路线的一个前提被证伪了**:我以为「提现单列表随账号快照持久」,
回源确认**不成立** —— `submitWithdrawal`(`src/store/app.ts:1253-1285`)建单后
只改内存,不落盘;全文件 20+ 处落盘调用无一在这条路径上;唯一的 watcher 管的是首页统计;
真正会落盘的「到账推进」要等几小时后到账时间到了才触发。
**用户提交一笔 → 按 F5 → 今日笔数回 0 → 闸当场失效。**

这不是路线错,是路线缺了一块地基。地基补上(建单成功后落盘,失败按本文件既有范式回滚内存),
路线成立。**顺带**:同一个根因还架空了换址闸(它读在途单列表),那是本包之外的既有缺陷。

### ② 是不是结构导致同型必然复发?

**是。** 五组注入全部逃脱,不是五个疏漏,是**一条共同结构**:

> **我写的判据描述的是「当期代码长什么样」,而不是「行为必须是什么」。**

- A/B/C 逃脱:固定靶只覆盖**我想得到**的输入形状(列表 ≤4 行、时间戳同质、时钟写死一个常量)。
  想不到的形状天然不红 —— 靶子的覆盖面等于我的想象力,而缺陷恰恰住在想象力之外。
- D 逃脱:正向判据用 `includes` 查字面串却**不剥注释** —— 字面串存在 ≠ 那行代码在执行。
  本文件第 523-524 行自己写着「正反两侧都要剥注释」,我只在反向侧做了。
- E 逃脱:反向判据是**禁名清单**。清单是封闭集合,而「再存一份计数」的写法是开放集合。

这与原始缺陷是**同一条结构**:钉名字、钉形状的判据,在被钉对象改名或消失时安静地永远为真。

### ③ 同型族的共同根因 → 一条根治,禁止逐个打补丁

族 = 「判据钉在形状上」。三条结构性替换(不是五个补丁):

| # | 替换 | 一次性根治 |
|---|---|---|
| **G1** | 计数函数改用 **property-based 对照独立参考实现**:随机 now(跨全天/跨月)× 列表长度 0..50 × 今日/往日/未来混排,断言与**另写一份**的日聚合结果逐组相等 | A / B / C —— 覆盖面不再等于我的想象力 |
| **G2** | 所有源码级判据**正反两侧都剥注释**,且剥到**行尾注释**与 `<!-- -->` | D |
| **G3** | 反向判据从**禁名枚举**改成**集合等式**:登记「参与日限判定的持久化 storage 键」与「日限判定的消费点」两张台账,与磁盘实际集合做等式比对(照抄同仓 `selfcheck-staking-cas.mjs` 的 `CAS_CONSUMERS` 写法 —— 那条是自校验的) | E |

**禁止的做法**:给 A 补一条「5 笔也要算」的靶、给 E 的禁名清单再加一个名字。
那是把开放集合当封闭集合修,下一个形态照样过。

### ④ 层级归位

| 层 | 落点 |
|---|---|
| 能机器测 | G1/G2/G3 三条焊进 `selfcheck-fastlane.mjs`;另加**断言数下限**(审计实测:整节删掉后 `73 pass / 0 fail` 且 exit 0,删除向零覆盖);`samples.stores` 这类手写装饰数改为派生 |

| 跨任务心智 | 「红测只能证明**我想到的**破坏会被抓;想不到的那类要靠 property/集合等式,不能靠加靶子」→ memory |

## 结论

**不是方向性错误,是结构性错误,且集中在门这一层。**
按铁律「确有结构问题 → 先改结构再继续 R」:本轮先落 G1/G2/G3 + 地基(建单落盘),
**不逐条打补丁**;结构改完再跑 R2,其余 P1/P2 在 R2 的新门下重新判定。

### 🔴 自查过程中抓到我自己的第二次同型错误(必须留档)

按审计提示,我一度给计数函数**加回** `typeof at !== "number"` 收窄,并写了段注释说它挡住了
「字符串时间戳静默计 0」。注入验证时 **0 fail** —— 我又造了一个红测证明不了的防御:
字符串走的是字符串拼接,算出的日序离今天十万八千里,**加不加这道收窄,结果都是 0**。

这是同一天内第二次犯同一个错(第一次是原始版本里的 `Number.isFinite`)。
两次的共同点:**我按「这个输入看起来很脏」加防御,而没问「有没有输入能区分它在不在」。**

- 已撤回该收窄,注释改成诚实版:说明「加消毒救不了,真正的解在契约层」;
- 靶子标题改成 `⚠️ [现状记录·非保护]`,避免读的人以为这一面被守着;
- 契约风险记 HANDOFF **U-7**(后端下发字符串/ISO 时间戳会让日限再次静默失效);
- 心智层规则写进 memory:**红测不只验哨兵,也验被测代码 —— 删了没红先问它是不是死的**
  ([[feedback_redtest_exposes_dead_defense]] 已在本会话建立,本次是它的第二个实例)。
