# 自造控件键盘可达性 · 全仓基线整改

Status: **Shipped** · 分支 `pkg/k1-keyboard-a11y` · 2026-08-12
起因:包 z2(提现日限)三轮审计顺带发现,独立成卡。

## Why —— 根因不是 151 个 bug,是一个架构缺口的 151 个症状

原生 `<button>` 白送键盘行为,没人给 `<button>` 写 keydown。本仓禁用原生 `<button>`
(uni 默认 chrome 过重:border + min-height + ::after hairline + bg,PITFALLS P-036),
于是**丢掉了原生按钮免费附带的键盘语义,却没有补上替代层**——每个自造按钮只能各自手搓
`@keydown.enter/.space`,搓漏了 151 处。

浏览器实景复核:`tabindex` 确实落到 DOM、`focus()` 确实成功,也就是**焦点能停上去、按 Enter
没反应**——最坏的组合(读屏念出「按钮」,键盘用户按了什么都不发生)。WCAG 2.1.1 不达标。

## 量面(自己扫的,不是采信卡片里的 147)

写了模板解析器扫全仓——Vue 属性会跨行,`grep 'role="button"'` 一行只数一次,属性分行写的
控件会漏,这正是 147 与实测值的差异来源。解析器抓到的 206 个 `role="button"` = 164 + 42,
与 grep 总数对得上。

| 类别 | 数量 |
|---|---|
| 有可激活 role + tabindex,**无 keydown** | 108 |
| 有可激活 role,**连 tabindex 都没有** | 43 |
| **本卡面** | **151** |
| 手写 keydown **缺 `.prevent`**(门跑出来的,量面时没预见) | 27 |
| 纯 `@click` 零无障碍属性(对读屏不存在) | 372 → **独立卡** |

🔴 **别把本卡读成「全站键盘可达」**:本卡覆盖的是**已声明无障碍身份**的 223 个控件。
连身份都没声明的还有 372 处 —— 真实键盘可达率约 **223/595 ≈ 37%**。其中包括**注册用的滑块
验证码**(`captcha-slider.vue` 的关闭/刷新/重试都无 role/tabindex,滑柄只绑 `@touchstart`
与 `@mousedown`),即**纯键盘用户目前仍无法完成注册**。这批归独立卡,但结论必须写在这里,
不能让「223 控件全部可达」被读成「全站都能用键盘」。

问题面比卡片描述更宽:仓里还有 `role="switch"/"link"/"tab"/"option"` 同族控件,只盯
`button` 的判据天然漏掉它们。判定用的是 **ARIA 规范里的可激活 role 全集**(封闭集合),
不是控件名清单(开放集合)。

## What changed

1. **新增平台层** `src/lib/a11y-activate.ts`(~40 行)+ `App.vue` 挂载一行。
   声明 `role` + `tabindex` 即得到键盘激活,和原生 `<button>` 一样。**零调用点改动**,
   151 处与未来所有新控件一并覆盖。挂载点在 onLaunch 两处 early return 之前——晚一步,
   退役路由页和静态评审页就整页没有键盘可达性。
2. **43 处补 `tabindex="0"`**:焦点落点无法由运行时补(补了也会与 SSR/首帧时序打架)。
3. **27 处补 `.prevent`**:原本同一控件 `.space` 带 prevent、`.enter` 不带,两个键待遇不
   一致;不带 prevent 会被平台层判成「没人管」而双触发,且 Space 会连带翻页。
4. **tracking 页禁用原因关联**:`aria-describedby` 指向可见的原因文本(复用已有元素,不加
   sr-only 副本)。此前读屏念完「已禁用」就没了——为什么禁、什么时候能再试,只有看得见的人知道。
   写法抄仓内既有先例(login/register)。

## 机器门(构造性)

`scripts/a11y-activate-gate.mjs` —— 遍历「全仓每一个模板元素」这个开放集合,检测**失败特征**,
不枚举任何控件名/页面名:

| | 判据 |
|---|---|
| A | 有可激活 role,却完全没有 tabindex |
| B | `tabindex="0"` + `@click`,却没有 role |
| C | 手写 enter/space keydown 没带 `.prevent` |
| D | 平台层缺失 / 未挂载 / 被空壳化 |
| E | `aria-describedby`/`labelledby` 指向不存在的 id **或同文件 id 重复**(读屏静默念不出) |
| F | 静态判不出 role/tabindex/可点性 —— **不阻断但必须可见**,并钉数量上限 |

配套 `a11y-activate-behavior.test.mjs`(10 断言,真按 Enter 看有没有 click)与
`a11y-activate-gate.redtest.mjs`(逐条注入违例证明每条判据真会红,含还原校验)。
两条链都登记:`verify.sh` 的 `a11y_activate_gate` + `package.json` 的 `test:a11y-activate`。

> verify.sh 里原有 4 条具名 keyboard-accessible 哨兵保留(它们额外锁具体控件的具体行为),
> 但已就地注明**不要再往那张清单里加**——枚举式判据守住 4 个控件时,问题面是 151 个。

## 审计(4 份独立 + 1 份修法证伪)

四份互不知情的审计共报约 50 条。**它们抓到的第一批问题里,有相当一部分是这道门自己的假绿面**——
门看不见动态绑定的 role(仓内 3 处,其中 2 处是真缺陷,被塞进「本门不判」的桶里);
`tabindex="-1"` 满足判据;根 `<template>` 带任何属性会让整个文件被静默跳过;
以及最要命的一条:**新增的行为门没在契约表里登记,导致 `npm run verify` 在更早的一步就断掉,
我的三道门在那条链里一次都没执行过**——而我当时"验证"两条链的方法只是查字符串在不在链里,
没验证链走不走得到。形状判据的又一次失败,发生在一张主题正是批评形状判据的卡上。

据此把门重写(v2),同族缺陷用一条不变量根治,不逐个打补丁:

| 族 | 根治方式 |
|---|---|
| 判据与平台层不同源(松紧不一) | role 表**从平台层源码提取**,提不到就红;两边永远同一张表 |
| 解析器静默漏扫 | **基数不变量**:`<tag` 出现数必须等于解析出的标签数、有 template 的文件数必须等于 .vue 数 |
| 静态判不出的被当成"没问题" | 单列 **F 类**上报:个体不阻断(多是合法写法),但钉上限——判不出的面悄悄变大就是判据在退化 |
| 门自身被掏空 | 覆盖面 floor + 断言红测与行为门在盘上且用例数达标 |
| 红测覆盖不全 | 模板类判据改注入**临时新建文件**(真源文件一个不碰,顺带覆盖"整文件漏扫"这一族) |

红测从 8 条扩到 18 条,含**可见性断言**这一新类型——F 类故意不阻断,拿阻断断言去测它
只会得到一条永远失败的红测。

## 修法证伪(4 个提案,只有 1 个活下来)

按「默认用法 = 证伪修法,不是验收成品」派独立 agent 证伪,结果拦下 3 个错误修法:

- **弹层几何命中测试 → 不可行**:遮罩层级不单源(遮不住页头/状态栏)、134 处手写 keydown 的
  控件根本不走本层、`pointer-events:none` 子树返回祖先而被判"可见"、动画期间包围盒失真会让
  真按钮按不动。是拿脆弱的几何启发式治症状,正解是弹层自己上 `inert` + 焦点陷阱。
- **移除置灰闸 → 收益远低于宣称**:逐条核过 14 个置灰控件,handler 全部自带守卫(不会放行),
  但只有 2/14 会给出原因,其余 12 处本来就是静默返回——删闸只是把"什么都不发生"换成
  "什么都不发生",真问题是那 12 处缺反馈。且删闸新开一个风险面(合成 click 会冒泡到可点祖先)。
- **Space 移到 keyup → 不可行**:keyup 是新事件对象,keydown 的 `preventDefault` 不传递,
  67 处手写 `.space.prevent` 会双触发;还会让"空格打开国家码面板 → 焦点移到关闭按钮 →
  keyup 落在它上面 → 刚开就关"。
- **按住防抖 → 采纳**:`ev.repeat` 早退,并补注释边界(只覆盖本层激活路径,不含那 67 处手写)
  与注入测试。

## 第三轮:弹层焦点管理 + 滑块验证码(主人 2026-08-12 拍板扩范围)

审计指出本轮补 tabindex **放大了**一个既有缺陷:遮罩只拦指针不拦键盘,弹层打开时能 Tab 到
背景并激活(背景里有提现、下单这类按钮)。我原本推荐只修全局确认弹窗(覆盖面最广),
主人拍板**全部弹层都修**,滑块验证码也纳入。

**精确枚举**:判据取自 CSS 事实(`position:fixed` + 四边贴边)且**遮罩元素自身可开关**——
先前的粗判把登录页、注册页这些常驻的整页外壳也算成了弹层。实测 **15 个真弹层,此前只有 1 个**
做了焦点管理。

**抽共享能力** `src/composables/use-dialog-a11y.ts`:焦点移入 → Tab 只在层内循环 →
Esc 关闭 → 关闭后焦点归还触发控件。写法抄仓内两个已做对的实现,不自创。
16/16 全接入(15 个 + 1 个原本就对的)。

几处刻意的设计:
- **不给背景上 `inert` 而用 Tab 陷阱**:uni 的弹层就渲染在页面自己的组件树里,拿不到稳定的
  "页面根"来上 inert;Tab 陷阱不依赖 DOM 结构,对键盘用户等效。
- **close 可以不传**:断网遮罩只有「重试」一条路,没有取消语义;给它接 Esc 等于凭空造一个
  "看起来关掉了、其实什么都没做"的出口。
- **可见性用 `getClientRects` 不用 `offsetParent`**:后者对 `position:fixed` 元素恒为 null,
  而弹层里常有 fixed 吸底操作条 —— 用错会让 Tab 停不到确认按钮上(实景验证时发现)。

**滑块验证码**(`captcha-slider.vue`):关闭/刷新/重试补身份;滑柄加 `role="slider"` +
方向键移动 + Home/End + Enter/Space 提交,**复用与拖拽同一条提交路径**(不另开分支,
免得两条路的风控与失败态各走各的)。它是登录 / 注册 / 改提现地址三条路的必经关卡。

**新焊第 6 道判据 G**:可开关的全屏遮罩必须接焦点管理。判据同样从 CSS 事实推导,
不枚举组件名 —— 新写的弹层天然进判定域。红测 20 → 21 条。

### 撞上一个门与门的正面冲突

视觉门规定「带填充的容器一律零描边」且**把 outline 计入描边**;而无障碍要求「焦点必须可见」
(WCAG 2.4.7),焦点可见的标准实现**正是 outline**。弹层焦点自动移入后,浏览器给关闭按钮
画了焦点环,视觉门就报一条新增违例 —— 而那个类的样式里根本没写过 border。
两道门方向相反时,任何源码状态都不可能同时绿。
修法:视觉门扫描前先卸掉焦点,并在代码里写明边界(焦点态不属于"设计描边")。
该门自检 35/35 仍通过,判定能力未被削弱。

## 已知限制(写明,不假装覆盖了)

- **App 端未实测**:本层由 App.vue 的 onLaunch 挂载,而 uni 的逻辑层与视图层分离,逻辑层是否有
  document 我没有在真机验证过。若没有则该端不生效(安静跳过,不崩)。该端读屏走原生
  accessibility API 直接派发 click,不经过 keydown,影响面主要是「App + 外接物理键盘」。
- **弹层背景可穿透**:遮罩只拦指针不拦键盘,而本轮补 tabindex 放大了它。已在平台层注释里写明
  本层不管这件事,正解归弹层焦点管理专项。
- **F 类 6 处判不出**:5 处是 `v-on` 对象展开藏住了事件绑定(静态看不出绑了什么),
  1 处是 `wallet-cards-new.vue` 的 `<label role="switch">` 自身没有 click handler。
  最后这处**已实景证伪**:它编译成 `<uni-label>`(不是原生 label,浏览器自动转发不适用),
  但真键盘按 Space 后 `aria-checked` 从 true 翻到 false —— 平台层合成的 click 被 uni 的
  label 实现正确转发到了内部 checkbox,不是缺陷。门持续报数,不静默。
