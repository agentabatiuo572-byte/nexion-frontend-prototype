# 强制结构性反思(2026-08-04)· 触发:同型缺陷跨两轮复发

**触发条件**:`~/.claude/CLAUDE.md`「多轮不收敛 / 同型复发 → 强制结构性反思」——同一类型错误在不同轮次反复出现(≥2 轮同型)即强制,须先产出书面结论才允许继续下一轮 R。

## 一、同型事实

| 轮次 | 缺陷 | 形态 |
|---|---|---|
| R1 | 试用时间边界判定散落 4 处、各自手写 `now >= 边界` 比对 → 越界仍可转化(P0) | **单一真理散成多份** |
| R2 | 结算页一半读未推进的原始 `status`、一半读实时解析器 → 拼出用户没见过的净额并扣款(P0) | **同一根因,换了个消费者** |

R1 的修法(抽单一纯函数 `resolveTrialAt`)本身是对的——R2 的缺陷不是它没用,而是**它只被应用到了定义模块内部,没有覆盖消费者面**。

## 二、四问

**① 根本路线选错没?**
没有。「时间边界收敛成单一纯函数」这条路线在 R2 中被反向验证:凡是走了解析器的调用点(poll / convert / eligibility / 影子累计)在 R2 一条缺陷都没出;出事的恰恰是**没走解析器的那个消费者**。路线正确,覆盖不全。

**② 是不是结构导致同型必然复发?**
**是。** 结构缺陷在于:引入不变量时,我们扫的是「**定义面**」(store 内部还有没有手写比对),没扫「**消费面**」(谁还在直接读原始状态)。而后者是开放集合——今天扫干净了,明天新写一个页面照样可以 `freeTrial.status`,没有任何门看得见。R1 焊的接线门只断言「free-trial.ts 内无残留手写比对」,方向朝内;消费者在门的视野之外。
**这与已登记的「整套门共同漏掉删除方向」同构**:门只遍历它知道的成员,不知道的成员不会被任何遍历走到。

**③ 同型缺陷成族的共同根因(一条)**
> **封装未被机器强制:原始状态 ref 对全工程可读,而「必须经解析器」只是约定。**

**④ 层级归位**
- 机器可测 → 焊**封装门**(下节),不是写约定;
- 语义判断 → 已在 skill/派单纪律里(「修一处必扫全站同形」);
- 跨任务心智 → 记忆条目 [[feedback-single-source-must-gate-its-consumers]](本轮新增)。

## 三、结构性改动(先改结构,再继续 R)

新增 `scripts/selfcheck-trial-encapsulation.mjs` + 焊入 `verify.sh`:

1. **消费者台账在门脚本里**(不在被查文件里)——防止「删掉消费者的同时把台账那行一起删」这类同批编辑绕过(踩坑出处:2026-08-03 基线放进被查对象自己);
2. **白名单逐条写理由**,新增未登记的消费者一律红;
3. **钱路径文件绝对禁止**出现在消费者名单里(结算 / 提现 / 订单 / 账单 / 账户),即便被加进白名单也红——钱只认解析器;
4. PASS 行打样本量(扫了多少文件、命中几处),防空集假绿;
5. 红测覆盖**两个方向**:新增未登记消费者必红 · 钱路径文件出现必红 · 判据自身被破坏(扫描目标改名)必红。

## 四、结论

**确有结构性问题,已先改结构(封装门)再继续 R。** 根因非路线错误,而是「不变量只焊了定义面、没焊消费面」这一覆盖缺口;该缺口现由机器门堵死,新消费者无法静默出现。
