## I2 · otpSend 场景化滑块判定(本包核心) **[机制]**

**范围文件**:`src/store/auth-otp.ts`

**做什么**:L164 判定 `sends.length >= cfg.captchaAfterSends` 改为规格 ③ 纯函数:`const captchaRequired = cfg.captchaAlwaysScenes.includes(scene) || sends.length >= cfg.captchaAfterSends;`。其余(ticket 显式出示 / 单次消费 / 一码一 / SendLog 只记成功)一字不动。**判定顺序保持 冷却 → captchaRequired → ticket 校验**(规格 ④「冷却优先于凭证」)。

**AC**(继承规格 ② ④)
- [ ] register 场景:24h 内 0 次发送、无票调 `otpSend` → `captcha_required`(改前是直接放行——这是本包唯一行为翻转)
- [ ] register 场景:持有效票 → 放行且票被消费(`ticketUsed: true`);同一票二次使用 → `captcha_required`
- [ ] register 重发(第 2+ 次)同样要票(不区分首发/重发——server 侧同一条判定天然满足,验收确认即可)
- [ ] login 场景:第 1、2 次无票放行,第 3 次 `captcha_required`(与改前逐位一致,回归)
- [ ] reset 场景:同 login 阈值规则(不在 alwaysScenes,回归)
- [ ] 冷却期内即便携带有效票 → `rate_limited`(含剩余秒数),票**不被消费**(冷却分支先返回,验 inspect 票仍 `ticketUsed:false`)
- [ ] 滑块失败/关闭不写 SendLog(既有行为,不得回归;dev bridge inspect sendLog 长度不变)
- [ ] `captchaAlwaysScenes` 置空数组(dev 临时改 config)→ register 回落次数阈值规则(规格 ③ 空数组语义)

**测试指令**:5173 console 走 dev bridge:`__nexgridAuthDev.reset(p)` → `send(p,"register")` 应 `captcha_required`;`send(p,"login")` 应 ok;`seedSendLog(p,2)` 后 `send(p,"login")` 应 `captcha_required`
