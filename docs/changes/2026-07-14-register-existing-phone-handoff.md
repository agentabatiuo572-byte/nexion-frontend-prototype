# 已注册手机号验码后自动登录 · Change Proposal

- **工作线**：④ uniapp
- **日期**：2026-07-14
- **状态**：Implemented（主人已于 2026-07-14 确认；PRD 正文同步仍待明确确认）

## Why（问题 / 动机）

注册页当前只校验手机号格式，OTP 通过后无条件进入设置密码，最终无条件创建账号。已注册手机号因此会重复走注册链，也没有“已注册”提示或自动登录。

## What changes（改动点）

- 发码阶段保持新旧手机号完全一致，不提前查询或披露账号是否存在。
- 注册 OTP 验证成功后由 mock 服务端账号目录返回下一步：新手机号继续设置密码；已注册手机号显示提示并复用本次 OTP 直接登录。
- 已注册手机号不以固定等待阻塞登录；目标页 toast 持续展示“已注册 / 正在登录”反馈，并以读屏状态播报。
- 已注册分支复用既有登录完成链，不再发码、不再输密码，也不执行 `signUp`、风险注册落表、新人礼、注册成功页或新账号 onboarding。
- 新账号最终提交前再次走账号唯一性闸门；若期间发生并发建号，复用当前已验证凭证转登录。
- 增加持久化 mock Auth 账号目录；旧成功注册数据只做一次受限迁移。迁移中目录写入临时失败会保留可验证的短期恢复日志，恢复后只补完该 legacy 迁移；正常 schema2 目录被删仍失败关闭。生产环境由服务端账号库和手机号唯一索引替换。
- 新账号先写 `pending` 保留位，风险/推荐/礼包/账单完成后才激活为 `active`；中断后的 pending 再验码仍继续注册，不得走老号直登跳过 K1 / onboarding。
- `pending` 同时冻结推荐码、礼包路线/金额和稳定业务引用；K1 落表必须返回成功，礼包余额与两笔账单分别按同一引用幂等补齐。登录态和 session 均在 `active` 之后才写，任何副作用间中断都不能留下已登录半账号。
- 账号目录保留 onboarding 完成事实；注册后默认未完成，老号直登恢复该事实，未完成者续走 onboarding，不能被 `signIn` 强制改成完成。
- bearer `verifyToken` 只留当前页面和 mock server 内存，不写 localStorage；登录重试复用非敏感幂等结果，不能重复创建 session。
- 注册前 K1 mock 同时执行 IP 24h 与同设备账号上限；同一支付工具只在关联账号数严格超过后台上限后升为强关联并带稳定原因标记。
- mock 的同步唯一性临界区只覆盖单个 JS 上下文；H5 多标签页不把 `localStorage` 冒充原子数据库，生产必须由认证服务的手机号唯一索引和事务兜底。
- **Out of scope（明确不做）**：不重做密码认证；不在 OTP 前提供 `accountExists`；不新建弹窗或登录页跳转；不扩展当前“注销账号”伪实现为真实数据擦除（否则同手机号派生账号会复活旧资产，需独立规格）。

## Impact（影响面）

- **页面 / 路由**：`src/pages/register/register.vue`、`src/pages/login/login.vue`；无新路由。
- **Store / model**：新增版本化 mock Auth 账号目录；扩展 `store/auth-otp.ts` 的一次性验证凭证和分流结果，保持 backend-replaceable。
- **i18n**：`register` / `authOtp` namespace，en/zh 同序镜像，终端不露内部枚举。
- **设计**：复用注册页现有错误块、CTA 和忙碌态；不新增视觉组件，不新增硬编码颜色。
- **PRD 章节**：§4.1、§4.2、§4.6.2、§16.2.1；实现验收后按 `nexion-prd-sync` 等主人再次确认再同步。
- **不变量风险**：账号枚举防护、OTP 单次消费、邀请 first-wins、老账号零新人礼、双语、H5/App 同链、刷新持久化。

## Done-when（2-4 条可证伪、行为级判据）

- [x] 新手机号注册 OTP 通过后仍进入设置密码，提交后账号目录只新增一次且正常进入新账号流程。
- [x] 退出并整页刷新后，同手机号再次从注册页验码：OTP 前无账号状态，OTP 后显示已注册提示并直接登录，从未出现密码步骤，也不再发送验证码。
- [x] 已注册分支前后风险注册记录、推荐关系、新人礼领取和 bonus 账单数量不变；刷新后仍保持登录态。
- [x] OTP 必须匹配手机号、场景和请求；验证凭证短时、只在页面内持有并一次性消费；type-check、verify、H5 双语实景和独立审查全部通过。
- [x] legacy schema1 迁目录的目录写入失败一次后可安全续迁；无恢复日志的 schema2 目录删除仍不能重建账号。
- [x] 同设备达到配置上限时注册不建号；支付工具超上限时形成强关联并带稳定原因，放宽任一阈值即可回到对应的非拦截/弱维行为。
