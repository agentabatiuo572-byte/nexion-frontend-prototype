# 强制结构性反思 · R5(2026-08-04)· 触发:同型第二次复发

**触发**:「多轮不收敛 / 同型复发 → 强制结构性反思」。R4 根治「资金变更的落盘失败被静默忽略」;R5 发现**回滚本身的落盘失败同样被静默忽略** —— 同一形状,深一层。

## 一、同型事实

| 轮次 | 缺陷 | 形状 |
|---|---|---|
| R4 | `bills.add` 返 null / 资金原语落盘失败 → 调用方按"一定成功"往下走 | **失败是静默的,调用方不知道** |
| R5-P0① ② | `restoreMoney(undo)` 返回值被丢弃(`money-receipt.ts:98/106`)→ **回滚失败了也弹"交易未保存"**,而钱已经扣了 | **同上,只是主语从"操作"变成"回滚"** |
| R5-P0③ | `stake()` 存储异常分支返回 `ok:true`(`staking.ts:212-215`),仓位只在内存 → 刷新蒸发 | **同上,且该文件自己 4 行后的注释明令禁止这么做** |

R5-P0③ 尤其说明问题:**同一个函数体内,冲突分支执行了"如实回报"的铁律,存储异常分支没有**——不是不知道规则,是**规则只被应用到了想到的那条分支**。

## 二、四问

**① 根本路线选错没?**
「资金变更必须与收据同生共死」这条不变量是对的,R4 的收口点也确实消灭了四处裸调用。**但它隐含了一个不成立的前提:回滚一定会成功。**

**② 是不是结构导致同型必然复发?**
**是,而且是数学意义上的必然。** mock 层有**两份独立存储**(账户快照 / 账单表),**没有事务**。于是:
- 「两边都成功,或两边都不发生」这个要求,客户端**做不到**;
- 每加一层回滚,那层回滚**自己也会失败**,于是需要"回滚的回滚"——**无穷回归**;
- R4 加了第一层,R5 就在第一层的失败路径上找到 P0。**R6 会在第二层上再找到。**

**这不是"再修一轮就好"的问题,是所选方案的能力上界。**

**③ 共同根因(一条)**
> **用"两次独立写盘 + 补偿回滚"去模拟事务,在没有事务的存储上永远关不上;每一层补偿都是新的失败面。**

**④ 层级归位**
- 机器可测 → 见下节结构改动;
- 语义判断 → 「失败路径也是路径」写进派单纪律;
- 跨任务心智 → 记忆条目。

## 三、结构性改动:两条路,必须选一条(不能继续加层)

### 路线 A · 消灭问题(推荐)
**把资金与账单合并到同一份存储行** → **一次写盘 = 原子**。
- 「钱动了账没记」在结构上**不可能发生**,不需要回滚,也就没有"回滚失败"这一层;
- 与"真后台单事务"的语义**一致**,将来接后端是收敛不是改写;
- 代价:一次存储层重构,影响面需评估(账单是分页读的,合并后读写粒度变大)。

### 路线 B · 承认上界(下策但诚实)
保留现状,但**明确停止追求"完美回滚"**:
- 回滚失败 → **不再弹通用"交易未保存"**,改为**响亮的终态**:「资金异常,请联系客服 · 交易号 X」;
- 失败快照**入对账队列**,留给后端对账;
- 在代码与文档里**写明这条上界**:客户端做不到原子,残余风险由后端兜。

🔴 **不许选的第三条**:继续加"回滚的回滚"。那是把无穷回归当工作量。

## 四、无论选哪条,本轮必须做的

1. **`stake()` 存储异常分支按同文件既有铁律改**——它自己的注释已经写明正确做法,只是没执行到那条分支(这条与路线无关,是纯粹的自相矛盾);
2. **`restoreMoney` 返回值必须被消费**——路线 A 下它会消失,路线 B 下它触发"响亮终态";
3. **结算页 `convert()` 挪到扣款之后**(或扣款失败时回滚试用态)——试用被消耗却没买成是不可逆损失;
4. **哨兵正则补 `addMany`**——多腿原语当前完全无监控;
5. **多标签页并发下 `restoreMoney` 写绝对值会凭空造钱**(审计给了完整复现:两标签页各失败一次,余额从 $100 变 $130)——这条无论选哪条路线都要修,且**必须用真并发靶验**。

## 五、结论

**确有结构性问题,且是所选方案的能力上界,不是实现瑕疵。** 继续在补偿链上加层 = 明知无穷回归还往里投工。**路线选择需主人拍板**(A 影响面大但一劳永逸;B 便宜但把风险显式留给后端)。

在主人拍板前,先做第四节那 5 项——它们**在两条路线下都成立**,不是白做。
