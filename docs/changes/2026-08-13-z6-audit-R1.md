# z6 扣款自愈 · 独立审计 R1(5 agent,冻结快照 09834c8)

审计对象是 worktree 物理快照,不是主树 —— 另一个会话当时仍在改主树,信号文件冻结不了它。

**R1 结论:修法方向被否决,不是打补丁能收的。** 详见下方「main 回源裁决」。

## main 回源裁决(已核实的)

### ✅ 采纳 · 方向性 —— 补扣的立论前提是错的

`app.ts` 头注称「全仓没有余额端点,余额的唯一持有者就是本 store」,整格补扣建立在这句话上。
**回源证伪**:`app.ts:700-723` 的 `refreshRemoteFleet` 在 `remoteApiEnabled && !fundsSandboxEnabled` 时
用服务端 `fleet.walletUsdt` **整体覆写** `usdtBalance` 与 `earningBuckets`。

档位判定(`api/runtime-config.ts:35-41`):生产无 env → `remote`;开发无 env → `sandbox` 但
`modeExplicit=false` ⇒ `fundsSandboxEnabled=false`、`remoteApiEnabled=true`。
**这两档正是补扣会跑、且会真扣本地余额的档。**

后果二择一:服务端值已含这笔 ⇒ **双扣**;不含 ⇒ 补扣的 −N 被下一拍重投影抹掉而幂等键已置位
⇒ **永不重试**,原缺陷原样回来。两种都比不修更坏。

### ✅ 采纳 · 既有裁决已明令禁止这种实现

`docs/changes/2026-08-11-z5-out-of-scope-findings.md` B 段:
> 🔴 **不可**无条件遍历 `app.withdrawals` 补扣 —— 2026-08-10 remote 对齐期建的存量单**全都没有**
> `wd-debit:` 键,一次性批量追扣会让用户余额无解释地掉一大截。范围必须用「提交时落一个本地
> 待扣款标记」钉死,只对带标记的单重试。

本实现正是被禁的那一种。**动手前没搜既有文档里对同一问题的既有裁决 —— 这是本轮最贵的一课。**

### ✅ 采纳 · 「扣了又退净 0」只对总余额成立

`app.ts:1414` 扣款时 `withdrawableUsdt = min(w, u−N)`;`app.ts:1444-1447` 退款腿头注明写
「只加回 usdtBalance,**不动 withdrawableUsdt**」(clamp 不可逆)。
⇒ 每走一次「补扣 + 退款」,可提桶永久少一截。这条损害路径是本次新增的
(改之前:从没扣过的失败单既不扣也不退)。

### ✅ 采纳 · 状态面完全没钉

补扣循环不看 `wd.status`,而 ② 退款腿只覆盖 4 种失败终态。
`confirmed` / `sent` / `processing` / `frozen` 被补扣后**没有任何对手方**,净 −N。
注释里的「净额守恒」被写成了整格的论证,实际只对失败终态成立。

### ✅ 采纳 · 门本身也不够硬(静态门审查实测出的绕过)

- 三条合取都是**全文件首次出现**的 indexOf,不含「在 reconcileBills 内」的作用域约束 ——
  实测:把真块挪到 ② 之后 + 上方插一段永不被调用的 decoy,三条合取全绿,而 runtime 门对
  「挪到 ② 之后」本来就 13/13 全绿 ⇒ **两道门同时绿,顺序不变量已破**。
- 循环源不钉:`for (const wd of ([] as ...))` / 整块包 `if (false)` 静态全绿(runtime 会红)。
  同文件紧邻的赠金格正是因这条红测才补了循环源正则 —— **同型缺陷 12 行之外复发**。
- runtime 夹具只造 `submitted` × 3 + `tx-failed` × 1 ⇒ 11 种状态覆盖 2 种;
  加一句 `if (wd.status === "confirmed") continue;` 两道门都绿,而 9 种状态的漏扣单永远补不上。
- `ASSERT_FLOOR` 保护不到本格:实测 118 断言 / 下限 112,整格删除后 `117 pass / 0 fail` 退出码 0。

### ✅ 采纳 · 守被调用方 ≠ 守调用点(命中既有铁律)

fastlane 那三格 `remoteApiEnabled` 扫的是**被调用方**函数体
(`applyWithdrawalDebit` / `refundWithdrawalDebit` / `refundFailedWithdrawals`),
接线门② 只比 `healAt < refundAt` —— **没有任何一道门看调用点**。
⇒ 给 `reconcileBills()` 首行加一句 `|| remoteApiEnabled` 早退,两道门 13/13 + 118/0 全绿,
而提现单只在 remote 建得出来 ⇒ 生产档自愈整格死掉。
同族 memory:`feedback_gate_guards_callee_not_caller`。

### ✅ 采纳 · runtime 门的其余覆盖缺口

- **注入不跨拍**:两次注入都在 setup 同步段内完成、13s 里失败早已消失 ⇒ 只测了「失败结束后补一次」,
  没测「失败持续时补到成功为止」。加一个 `const healTried = new Set()` 式的一次性内存台账,本门全绿 ——
  而 `reconcileBills` 头注自称根治掉的正是内存重试台账,fastlane 的反向判据只黑名单了 `pendingBillSettle`。
- **13 秒是墙钟固定值**,落在 2~3 拍之间:同一份代码在快慢机上两种结论。应改 `waitForFunction` 轮询终态 +
  用 DEV 探针单独断言 reconcile 执行 ≥2 次(拍数与结论各自可判)。
- **没有基数下限**:任一后续编辑把某几格挪进条件分支,脚本仍 `exit(fail>0?1:0)`,verify.sh 原样回显
  `N pass / M fail` 不校验 N。本仓已有两次「红门数掉下来被读成好消息」的同型事故。
- **夹具继承 demo 种子**:只归一了 `usdtBalance`,`withdrawableUsdt` 被注入夹到 1 且不还原;
  `after.listed===4` 只数 4 个 id、不断言列表长度 ⇒ 种子多一张单,补扣会把它也扣掉而余额算式静默失配。
- **注入命中哪条 return false 没有见证**:判据只有「返回 false」,任何新增的更早 return false
  都会让这两格照绿而测的是别的分支 —— 与本门自己为 amount 加的那格同类风险,只做了一半。
- `pageErrors` 收了不判(同仓 runtime 门普遍带 console-error=0);日志名无 `$$`,多工作树并发互相覆盖。

## 待裁决(R2 处理,不在本文件下结论)

- 补扣循环内 `adoptAccountSnapshot` 换掉 `withdrawals.value`,而 `for...of` 迭代器锁定旧数组 ——
  旧数组独有的失败单被扣后不在 ② 视野内。
- ② 退款腿无 try/catch,而 ⓪b 有 —— 脏单会让 ⓪b 落的 −N 无人退。
- remote 档幂等键只活在内存(`persistAccountSnapshot` 首行早退),刷新即失;
  注释「判假不再是终局」在该档不成立。
- 扣款失败无因分诊:余额不足与落盘失败共用一条重试路径,无退避、无上界、无用户交底。
- `withdrawalDebitKey` 未导出,门脚本仍手拼字面量 ⇒ 单源化不完整;`wd-refund:` 同族未收口。
- `withdrawalDebitApplied` 在 sandbox 档恒假(apply 早退不置键),今天只靠 `reconcileBills` 首行早退掩着。

## 同形全扫的结果:「失败后无自愈 / 无交底」是**全站族**,不是提现独有

第 5 个 agent 逐个读过 **55 处资金原语调用点** + `persistAccountSnapshot` 的 27 处
(**12 处接了返回值,15 处丢弃**)+ 60 处 claim/redeem/settle/mark 类 action。
报回 10 条 P0,**全部是范围外的既有缺陷**,与本包无关,但同族:

| 族 | 现象 |
|---|---|
| 入金三轨 | 收据写入返回值被丢弃 ⇒ 钱已入账、分录永久缺失;对账循环只遍历 `withdrawals`,没有 topup 格 |
| 购买 / 组合 | 收据返回值丢弃,组合还无条件报成功 |
| 质押开仓冲正 | 冲正返回值丢弃,退款可能失败而页面照弹「开仓失败」 |
| 以旧换新 | 回滚只改内存不落盘 ⇒ 重开白送一台设备 |
| 收益里程碑 | 用了非幂等的写入 + 标记落盘失败静默 ⇒ 重开二次发钱 |
| 签到 / 连签 / 质押平仓 / 转盘 | 先消费资格再发钱,失败即永久归零;转盘 ref 带时间戳 = 假幂等 |
| `settle()` 收益入账 | 落盘返回值被丢弃(同文件其余 12 个原语都接了) |

🔴 **这条推翻了 `src/lib/withdrawal-bill-drafts.ts:13` 那句「资金分录里只有这一族没有自愈路径」** ——
入金与购买两族同样没有。本包当初正是照着那句话把提现当成孤例来修的。

⇒ 若主人决定治这个族,按 nexion-audit 铁律 ③:**族必须用一条不变量或一道机器门根治,禁止逐个打补丁**
(例:焊一道门,禁止丢弃资金原语与落盘函数的返回值)。

两者对同一个数各写各的。本次补扣只是把这个既有冲突的触发频率从「每笔一次」放大到「每拍一次」。
