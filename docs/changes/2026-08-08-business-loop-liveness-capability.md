# 业务循环存活性能力契约

- 日期：2026-08-08
- 状态：H5/local-mock 实现与行为门通过；生产后端、原生真机与 Janus 端到端仍待验收
- 来源：`docs/前端产品更新日志.md` 2026-08-07「登录守卫补洞（续）」明确标注的第三条腿，以及 `docs/audit/2026-08-07-probe-and-guard-audit.md` 的独立复现。

## 能力声明

已登录、已完成引导且当前会话状态仍为 `active` 的用户，从静态评审页返回任意业务页后，无需切后台或刷新，到账推进、退款/账单对账、试用状态、订单、里程碑与收益模拟会在下一次守卫节拍内自动恢复；Janus C2 会重新启动既有客户端调度，实际远端通信仍以远端 API 已启用、令牌有效及端到端验收为前提。

本能力仅描述当前 H5/local-mock 生命周期编排，不构成真实后端会话、生产资金结算、原生真机或 Janus C2 生产接管通过的声明。

## 约束与不变量

1. 静态评审页、登录/注册/引导白名单页、未登录态、会话失效态和 App 后台态不得运行业务循环。
2. 权限/会话守卫不是业务循环，只随 `onShow`/`onHide` 成对启停；停止业务循环不得停止守卫。
3. 业务循环启动必须幂等：守卫每秒检查时，已运行的循环不得被反复清空并重建。
4. 所有业务循环必须由一个集中出口启动、一个集中出口停止，新增循环不能只接 `onShow` 而漏掉站内路由自愈。
5. 恢复时先执行一次离线缺口结算与到账/账单对账，再启动周期任务，避免等待下一个 5 秒节拍。
6. 停止 Janus C2 调度时必须同时中止当前在途请求并使旧代次失效；旧响应不得在停机后写运行态、删除稳定重试事实或发送后续 ACK。
7. 业务延迟回调不得直接创建未登记 `setTimeout`；必须进入统一 registry，并在停机时全部取消、执行前再次校验生命周期和会话。
8. 入金 local-mock 的链上确认和银行锁价过期延迟任务也属于业务循环；必须随集中出口暂停/恢复，暂停期间不得确认入账或改写意向单状态。

## 接口、数据与安全边界

- 本轮不新增后端接口、不改变资金算法、不改变会话模型，只修 App 生命周期编排。
- 继续使用现有 `useAuth()` 与 `useSession().validate()` 作为启停前置条件；条件未知或无效时 fail-closed。
- 不在静态评审页执行任何用户数据写入；路由离开后必须重新通过认证与会话检查。

## 非目标

- 不把本地模拟轮询改成生产 SSE/Webhook。
- 不替代原生端缓存恢复矩阵、真实后端资金故障注入或 Janus 真机验收。
- 不处理同一审计中的探针参数、零覆盖假绿和路径归一化工具问题。

## 验收门

- 结构门能证明：业务循环只有集中启停出口，守卫路由检查会触发自愈，且删除自愈、遗留 interval/timeout 后红测必失败。
- H5 从业务页进入 `entry-surfaces`，再站内返回业务页，不刷新、不切后台；1/4/5/6 秒周期任务均恢复，已登记的延迟回调在评审页不得执行。
- 未登录与会话失效路径仍只保留守卫，不得恢复业务循环。

## 2026-08-08 验证结果

- 结构门：集中启动/停止、守卫驱动恢复和 11 组变异红测通过（含未登记 interval、App 未登记 timeout、业务依赖模块内递归 timeout、已登记 timeout 未停止，以及入金确认引擎漏停/漏检查的反向对照）。
- H5 行为门：业务页 → 静态评审页 → 业务页，1/4/5/6 秒周期均先停止后恢复，延迟业务回调被取消；真实创建的 local-mock 链上入金在评审页停在 `detected`，返回业务页后才重新推进；未登录对照未启动业务周期，2/2 场景通过。
- Janus 停机取消门：HTTP RequestTask abort、延迟 report 回包、延迟 runtime apply 三层均通过；取消后不继续查命令、写运行态或发送 ACK。
- 既有守卫行为门：评审页进入、业务深链、已登录反向对照 3/3 通过。
- `vue-tsc --noEmit` 与 H5 production build 通过。
- `npm run verify` 会自动启动隔离 H5 server 并强制执行两个 Playwright 行为门；不再因外部 dev server 未启动而跳过后报绿。
- 本轮没有做真实后端资金故障注入、原生真机或 Janus 远端 60 秒同步结果验收，上述范围继续保持 HOLD。
