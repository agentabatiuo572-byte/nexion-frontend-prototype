# 2026-10-25 UI / UX 审查与实施记录

基线：APP `origin/test` = `e6d9b150`；H5 `origin/H5` = `7c61334`。旧原型与正式代码有差异，以下将实际修改、已存在的成果和待联调项分开记录。旧方案里“待拍板”不再要求重复审批，用户已授权选择最佳方案并执行。

## 核心判断

页面的主要问题是层级竞争：业务内容、促销、导航同时使用发光、圆角和玻璃，所有内容都像主操作。单纯删除卡片虽然清爽，却会失去产品质感。采用“平静的内容底板 + 有辨识度的插图 + 玻璃操作控件”：玻璃服务于导航和操作，商品、券和试用用内容本身形成视觉重点。

## E 章节决定

1. **收益表达**：预估与实际分开；不编造统计区间，不用“你将赚取”承诺结果。试用抵扣不能包装成可提现余额。
2. **注册人数**：采用真实注册数。后台起跳值/跳动频率不作为真实注册人数展示。可独立设计明确标注的运营指标，但不是本次真实人数的来源。在线设备仍沿用现有发布接口；其计数来源需后端验收，不在前端捏造新数据。
3. **术语**：团队层级分成、直接邀请奖励、平衡匹配、团队结构。资金规则和费率不因改名改变。已确认最新中文团队界面不再使用“业绩”，保留“算力额”。三语相关主要入口同步。
4. **商品规格**：保留当前服务端目录，图片、库存和规格缺失时正常降级。规格只在详情查看；不把旧原型的占位参数抄进正式目录，不替运营核实硬件真实性。
5. **设计规则**：不采用虚构紧迫感、先支付后披露条款、弱化取消或强迫逐屏转化的旧指导。关键条件应在操作前可见，取消/返回应可用。
6. **第三方背书**：移除内置 MSB 占位编号、PwC、融资金额、客户数量、LinkedIn 核实和 HackerOne 承诺等无凭据词条。正式资料继续消费已发布资源，真实证明文件需资料负责人提供。
7. **源码说明**：删除等级模块中“上钩/画大饼”等操纵式注释，改为说明条件、权益与数据来源。

## 八级等级与消息计数的边界

- 正式等级阶梯已经由 `/api/config/v-ranks` 驱动，本轮用 V0–V8 配置实际操作了页面，确认只出现 9 行（V0 为初始状态，8 个可晋升等级），每级均能查看条件、权益和奖励。
- 不把真实账号的 V9–V12 在前端静默改成 V8，也不改奖励计算或迁移历史权益。服务端启用八级表、旧等级迁移与权益保护必须一起确认。兼容旧协议的类型与测试仍保留。
- 营销消息从“资金”筛选移出已实现；“营销不计铃铛未读”需要服务端全量计数口径一起调整。客户端只拿到分页消息时不能自行扣减全局计数，否则跨页计数会再次打架。
- 无目标的通知允许展开完整内容；具有目标的通知经过原有服务端动作记录读取最终目的地，避免客户端猜测详情地址。
