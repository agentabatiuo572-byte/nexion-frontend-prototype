## 缺陷与修复

### 658：原生通知渲染中断

通知摘要使用的 Unicode `Mark` 属性正则在当前旧 Android 引擎报 `Invalid property name`，中断共享消息页渲染。原始截图是点击通知后仍残留服务页的状态，不能把该图片说成完整黑帧；运行异常日志才是根因证据。

复用已有 regexpu 生成流程，输出旧引擎可解析的完整组合附标正则，保留中英越组合音标、摘要长度及展开行为。独立比较 Unicode 全码点与原正则结果，差异为 0；没有将范围缩减为拉丁字母。独立检查原生产物正则均可按 ES2017 解析，不将其外推为整份 JavaScript 均兼容 ES2017。

实际操作：从首页铃铛进入消息 → 通知列表 → 展开真实欢迎通知 → 未读 1 变 0 → 打开目的地进入赚取页 → 返回消息。最终无临时诊断资源再次进入列表、展开正文，仍为全部已读，分类切换正常。

### 659：新用户客服票据被初始设置门禁误拦

当前新用户在 WebSocket 建立前，`POST /api/app/support/realtime-ticket` 就收到 428 `USER_ONBOARDING_REQUIRED`。老用户网页连接成功不能代替这个新用户场景。此根因不同于历史 328 的 Origin 问题，未改写其历史关闭结论。

后端仅将明确的客服通信方法/路径从业务初始设置门禁中分离，同时去掉客服 USER WebSocket 写入的同类误拦。JWT、会话撤销、账号禁用、会话归属、管理员写权限、消息幂等保持；订单、充值、提现等业务门禁及已下线工单接口保持。没有全量放开 `/support/**`。

TEST 后端发布后，同一个新用户无需完成资料，原生诊断资源自动恢复，观察到 `TICKET_READY → SOCKET_OPEN → AUTH_READY → RECONCILE_READY`。随后改用最终无临时诊断资源，进入服务分类没有不可用横幅；会话管理显示真实空态，联系专属客服可进入输入页面，尚未分配客服的说明与实际账户一致。
