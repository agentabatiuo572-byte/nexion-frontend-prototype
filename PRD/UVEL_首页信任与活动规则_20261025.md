# UVEL 首页、信任中心与活动规则（2026-10-25）

本规格覆盖推荐课程、网络脉搏、信任中心、原型全部十项活动及新增创世抽奖。适用于正式 App `test`、共享 H5 和 PC/后端 TEST；取代旧原型同功能的模拟数据、装饰性活动和本地领奖逻辑。实现与验收状态分别记录，本文件不是发布成功证明。

## 1. 推荐课程

推荐依据当前账号接口的完成状态：先选择未完成的精选课程，再按发布顺序推荐其他未完成课程。完成学习/测验后返回首页重新读取，推荐下一项；奖励由原课程服务发放，不因推荐切换再次领取。

卡片展示课程名称、真实时长、奖励、进度以及“开始/继续学习”。全部已完成显示回顾入口；尚无课程与读取失败分别显示对应状态，不能作为“全部完成”。首页进入课程携带来源，返回首页；课程中心仍按自身导航返回。切账号、语言、运行环境及离开页面后，旧请求不可覆盖新页面。支持中文、英文、越南文及窄屏。

## 2. 网络脉搏与 H9

网络脉搏保留“注册用户 / 在线设备 / 设备预估排名”三格，移除更新时间。注册用户读取 H9 的公布基数、月增长率和时间锚，由服务端按每月 30 天计算；在线设备使用 H9“首页数字增长”的同一持久化随机批次当前值。公开投影字段为 `publicStats.networkPulse`。

两个展示数字在配置重新读取时更新，不增加每秒请求，也不在网络脉搏另造随机序列。介绍页仍按既有批次逐秒显示。设备预估排名独立读取 `/api/app/network/device-rank`，按当前账号绑定手机的有效算力与模拟设备分布比较，不能使用账号设备总和或真实用户排名兜底。缺失/失败显示未取得状态，不能默认零；H9 数字不写入财务、设备或真实经营统计。

### 2.1 设备预估排名

PC H9 独立配置开关及 1–20 个设备档位，档位包括名称、占比、最低/最高 TOPS。占比合计 100%，算力范围为有限非负数且最低不高于最高；配置按版本校验并记录修改理由与审计。普通首页数字保存不得覆盖排名配置。

排名规模使用 H9 在线设备展示量 N，当前绑定手机占一个席位，其余 N−1 为后端生成的模拟参考设备。同一配置及规模使用共享快照；增长仅补样，降低使用稳定前缀。仅档位分布实际变化时建立新模型，开关切换、刷新与服务重启保留原模型；完全相同配置重复保存不增加版本。支持 1–1000 万台，规模为零、缺失或超过上限时返回不可用，不截断规模后伪造名次。名次等于严格大于当前手机有效算力的样本数量加一，同算力并列，名次在 1..N。此排名仅供参考，不产生收益、奖励或账务影响。

App 与 H5 显示同一账号绑定手机的预估排名。H5 仅查询，不进行激活、校准或心跳。无绑定或无有效算力显示“未上榜”；关闭、读取失败或未知状态显示“-”，提供说明或重试，不回退旧真实排名、账号汇总排名或本地随机值。点击排名可阅读三语说明，明确模拟设备分布、当前绑定手机及同分并列，不显示未经计算的 24 小时升降。

复用账号与运行环境隔离、并发请求合并及 10 秒缓存，不增加每秒请求。切换账号或环境时清除旧快照，迟到响应不得覆盖新范围。

## 3. 信任中心

使用整条圆角标题栏；平台介绍读取 I4 发布的 UVEL 文案，无简介时给出中性引导。页面提供“规则与资料”四入口：UVT 使用说明、服务条款、隐私政策、风险披露，对应现有正式页面，支持三语。I4 请求失败不阻断这些入口。

平台运行数据仅采用真实验证统计。公开资料仅展示已配置、可打开的有效链接；不能用厂商技术规格冒充平台审计、储备证明或合规资质。原型中的投资方、认证、审计机构、媒体、团队、交易所上线和虚构金额不是可直接发布的资料。保留真实资料缺失状态，不制造文件或无效链接。

### 4.1 页面和配置边界

“我的 → 账户”常驻“任务中心”入口，进入今日、本周、活动和成就页签；不因任务全部完成、任务读取状态或 H9 新手任务开关而隐藏。用户可经“任务中心 → 活动”进入活动列表、幸运转盘和创世抽奖。

转盘扇区按真实奖励金额与类型显示双行短标签，单位随语言切换，完整保留金额且不跨扇区或遮挡中心；奖池和中奖结果继续显示完整奖名。历史优先复用奖档、类型、金额均匹配的显示名，否则按该笔回执的类型与金额显示，不展示奖档内部代码，也不以当前配置金额改写旧奖励。

转盘历史时间由服务端返回显式时区偏移，客户端统一换算并标明 UTC；旧无时区值留空，不按终端时区猜测。

本人在同一活动 ID 与代码下存在真实转盘记录时，活动显示已参与、完成进度 1；仅打开转盘不算参与。关闭转盘后，当前可见活动列表（含任务中心内嵌页）重新读取一次参与状态；读取失败显示正常错误态，不轮询或自动补发抽奖。

非转盘活动进入专属详情，展示期限、玩法、当前进度、条件及复合奖励；“总奖池”不能显示为个人奖励。关闭、未开始、结束或不符合资格时不可参与。活动列表保留全部、进行中、预告、已参与、已结束筛选。区域竞赛使用本活动榜单，不能跳成全站排行榜。

区域竞赛列表和详情不显示无对应个人目标的 `0 / 1` 进度；地区结果中的奖励明确标为“地区奖励总额”。区域与持币活动的“我的到账奖励”仅展示详情接口 `myRewardAmount` 返回的当前账号、本活动真实已支付结果，以六位小数显示 USDT，不从地区总额或总奖池推算。未到账或旧接口缺少字段时不显示个人到账金额，真实已支付的 0 则显示 `0.000000 USDT`；持币天数等有实际含义的进度保留。此展示不改变原结算、分钱和回收规则。

限时升级的订单立减使用正式促销 `DISCOUNT_USDT`，仅面向购买人并按固定 USDT 金额抵扣；报价及订单保存活动立减与应付金额快照。活动立减不得超过对应商品行在既有套餐或券优惠后的应付金额，不静默截断，也不跨商品行抵扣。多商品订单允许单行立减后应付为 0，但含活动立减的整单最终应付必须大于 0，否则拒绝报价；支付时仍以该正数金额实付。App/H5 展示“订单立减”，以报价和订单的实际应付金额确认支付，不在客户端重复扣减，不显示为待到账奖励，也不进入钱包奖励记录。立减说明随订单保留，与其他真实奖励同时展示；退款按实际支付金额处理。升级额外创世票仍以已支付订单和已提交的促销预占为依据。

黑五复用正式 H7 百分比券：BF20 的 `percent=20` 表示减价 20%（八折），覆盖全部硬件，不以固定 20 USDT 或“优惠 $300 起”替代。活动详情将 `voucherId` 贯穿全场商城、商品详情和结算，不因可选 Pro 升级关联而过滤普通硬件。用户明确领取并选用 BF20；重复领券后重读券状态，已用或过期券不可再抵扣，不自动替换其他券。支持同款商品多台，暂不支持一张券用于多 SKU 套餐或拆为多笔。每账号一次领用、单笔使用在页面说明。只有符合 Pro 商品及参与条件时才显式携带升级促销；报价禁用自动促销选择，依次扣百分比券及固定升级立减，客户端不计算优惠。两侧叠加设置均须允许，活动、券与促销期限均由后台检查。

商城、商品详情和结算中的活动券提示使用公开券名或简洁的“活动优惠券”，不显示内部券 ID；券 ID 继续用于原领取和订单协议。报价、订单创建、恢复及支付后，商品名称均按现有 UVEL 品牌规则展示，历史订单名称快照保留原值，不因展示改名而改变商品或交易记录。

原生 App 从活动详情“去完成”进入商城时，必须打开商城标签并保留活动券、全场范围和可选升级促销上下文；不得回到首页或退回普通商城。当前原生运行时会再次编码路由参数，`onLoad.target` 仍保留一层外部编码；标签入口须识别并去除这一层，再解析内部业务参数。商品详情进入结算及套餐入口的 `items` 同样须兼容原生保留的外层编码，保持原 SKU 和数量；无效清单仍拒绝，不替换为默认商品。跨页面进入其他标签也保持原目的地及业务参数，已解码参数不得重复解码而改变内容。

H7/E08 使用新幂等键重复领取已发放券时，返回同一 `grantId`、`replay:true` 及实际状态（`AVAILABLE`、`USED`、`REVOKED` 或 `EXPIRED`）；已用券保持 `USED`，不重发、不重置。同一幂等键重放的原回执仍是当时快照，`GET /api/vouchers` 才是当前状态。App/H5 领取后必须读取最新券列表，仅当前确实可用才提示领取成功或进入报价；已用、撤销、过期或读回失败均不因旧回执变为可用。

H7 的 `claimSurfaces=[]` 表示不限领取入口，首页、商城、我的、收益共用相同判断；明确配置的非空入口列表仍只允许指定页面。首页入口与自动弹窗、商城券卡、通用领券入口及领取弹层都必须保留不限入口券，同时仍服从当前可领取状态、受众及弹窗频率，不因为入口不限而放开发放资格。PC 可保存空选择并显示“不限入口”；App/H5 不把空数组理解为隐藏，也不额外添加原本没有的页面入口。

H7 暂停投放或删除券定义仅停止新领取，不回收已发权益。App/H5 对已领取券按最新个人 `grantStatus` 和有效期判定：有效期内 `AVAILABLE` 保持可用并可进入报价，不因定义 `paused` 或已删除被标成过期；`USED`、`REVOKED`、`EXPIRED` 不能进入结算。已过期券归过期列表，尚未开始的券不可用但不误归过期；后台仍在报价、建单时重新校验。取消未付单后只按最新同一 grant 的 `AVAILABLE` 读回恢复可用，暂停不恢复新领入口或弹窗。

H7 正数发行上限是同一券所有发放来源共用的累计上限，0 表示无限；已核销、过期或撤销不恢复发行名额。额度耗尽后，未领用户的 `claimable` 与 `popupEligible` 均为 false，既有 grant 的身份和状态保留。列表读取不预占名额，读取后被他人领完时领取命令仍可拒绝并要求刷新；限额 1 的券被多个合格用户同时领取时，只能形成一个新 grant，其余额度耗尽，同一领取重放不再占额度。用户领取、转盘和晋升发券均遵守该上限。

邀请赠品与抽奖设备的功耗快照接受正数 W、原有 W TDP，以及明确的“（单卡额定）”“（显卡额定合计）”后缀（兼容 ASCII 括号）；保留商品原始配置，不移除后缀来绕过校验。范围、多数字、非正数或单位歧义不得生成设备权益。

复投总开关 `G.staking.app_visible` 关闭或缺失时，隐藏新增复投入口、关闭复投能力并禁止 H4 新参与；已有真实复投来源及票不清除，已达成但未领取者仍可按原来源领取补差票。退款、提前退出对应票的回收规则继续生效。

H4 新增玩法与开放设置，管理接口 `/api/admin/growth/event-rules`，写入单项带活动代码、配置版本及幂等键。开启前检查三语内容、合法期限、玩法字段、关联促销/商品、预算及库存。首次开启后冻结玩法和有效期；关闭后同一期不得重开。关闭阻止新增参与，不取消已形成的结算义务。两类奖池的既有参与者继续观察到原截止时间；关闭前已达标或已完成交易的个人奖励仍可见并可领取，关闭后不新增资格。旧内容创建入口也必须生成关闭草稿；未知玩法不能绕过发布校验。

幸运转盘的选中奖档因库存或资金限制降级时，只能发放当日库存仍可用的 UVT 安慰奖；每日库存为 0 表示不限。全部安慰档耗尽时，本次抽奖失败且保留免费次数或加抽券，恢复库存后可重试。积分、代金券、UVT 与 USDT 奖励分别进入对应权益或账务，不把券面金额显示成钱包到账。

App 与 H5 均须完整显示轮盘扇区及各奖项标签；转盘围绕圆心旋转，顶部指针、外圈及中心盖保持固定，停止位置对应服务端中奖结果。原生端不得出现空白扇区或奖项标签挤成一串，奖项名称中的特殊字符按普通文本显示。

活动卡片与精选活动按玩法显示图标：邀请为邀请人物、转盘为轮盘、区域竞赛为地球、加成为闪电、持币为盾牌，其余赠礼/促销显示礼盒。奖励摘要旁保留小号礼盒图标；App 和 H5 的不同尺寸均须完整显示图案，不得只显示底色方块。图标随现有主题配色显示，属于本地展示资源，不依赖额外图片请求。

抽奖失败按实际原因提示：活动未开放、次数不足或暂不可用时分别说明，并重新读取次数与记录；不得统一声称区块链繁忙或次数未扣。未决意图按账号、API 环境和活动持久保存，弹层、页面重挂载、App 重启及切号往返均复用原幂等键；无法读取或保存意图时不提交抽奖。首次请求确定拒绝才可结束该意图；一旦结果未知，重试的 400、401 或 409 只代表本次重试的结果，不能证明原请求未执行。只有同键返回的本次抽奖回执才能解除未决状态；刷新显示零次数或活动结束也保留原意图核对入口。切换账号或活动后不展示旧请求的迟到失败。

转盘幂等请求摘要包含 UTC 日期；服务端保留已完成命令回执，不因普通幂等期限到期而将旧命令作为新抽奖执行。未决请求重试前先读取当前活动状态；只有权威日期与原意图 UTC 日期相同时才允许同键重放。跨日或无法确认当前日期时仅允许只读核查，不再发送抽奖 POST，不自动生成新键，也不按金额、奖档或时间相近猜测历史记录归属；无法取得唯一关联的原回执时提示联系客服，避免过期键被当作新抽奖再次消费加抽券。

PC 活动与创世抽奖日期按 UTC 输入，支持分钟及秒，保存、刷新保留同一时刻，不重复拼接秒段或按浏览器本地时区偏移。用户界面中的转盘代币统一显示 UVT，协议资产码仍为 NEX。

App/H5 的活动期限、创世抽奖时间、促销支付期限及奖励回执时间均明确按 UTC 展示。中文格式为 `yyyy-MM-dd HH:mm · UTC`，英文和越南文为 `dd/MM/yyyy HH:mm · UTC`；终端时区或原生语言格式化能力差异不得改变显示时刻。无效日期保持空值，不显示错误时刻。

### 4.2 持币及区域结算

持币连续期依据真实余额变化，余额跌破门槛会中断；开启前没有观察记录的时间不能补算。区域来源取已验证账号国家，加入时固定；当前注册国家支持 CN/VN，未知国家不得猜测归属。

持币开始时间不早于活动开始、实际开启及首次达标观察时间三者中的最晚时间。钱包变为沙箱或删除状态时中断观察；活动领奖和创世抽奖均拒绝非正常、沙箱或已删除账号。活动时间按同一 UTC 口径存取，客户端、JVM 与数据库连接时区不同不得改变有效参与窗口。

区域订单必须实际支付，排除退款、撤单及退款处理中记录。截止结算读取并锁定相关成员和订单；奖池分配、预算、奖励入账及结果在同一事务完成，任一步失败全部回滚后重试。持币平分同样原子结算。精度为六位小数，余数确定分配，合计等于奖池。已成功结算的快照保持不变，后续退款不重新计算已完成活动奖励；不得把结算失败显示成已到账。

## 5. 独立创世抽奖
