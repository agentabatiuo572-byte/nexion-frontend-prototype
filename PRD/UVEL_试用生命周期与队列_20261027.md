# 免费试用生命周期与算力队列

权威：正式后端 AppTrialLifecycleService 的 state/start/convert/cancel；设备占槽规则归正式容量策略。商品、金额、时长、资格由接口发布配置和领取快照决定，不以演示值作为承诺。

#### [FEAT-TRIAL03] 持续状态与提前购机

**① 用户故事**：作为已领取免费试用的用户，我想在首页持续查看状态并随时购机，以便在已累计抵扣范围内完成转购，无需等满试用期。

**② 验收(GWT)+异常路径**
- Given 可领取且有容量 When 打开确认 Then 展示产品、配置天数、预计抵扣，确认按钮明确激活并开始试用；取消不领取。When 确认 Then 先激活中，幂等请求及权威读回成功后展示成功反馈，刷新仍试用中。
- Given 已结束且冷却已满 When 后台明确允许再次领取 Then 首页与详情可重新进入同一领取确认流程；读取失败或资格未确认不得开启下一轮。
- Given ACTIVE/GRACE When 返回首页 Then 状态卡保留；详情可提前购机。Given REDEEMED Then 入口进入正式设备管理，原试用不再占槽。
- Given 已领取生命周期状态 When 点击首页试用卡任意非重试区域或键盘激活卡片 Then 进入既有详情/设备管理目的地，不额外显示独立按钮；嵌套重试只刷新。未领取及未领取满容量状态保留原按钮和领取/管理权限。
- Given ACTIVE/GRACE When 首页展示状态卡 Then 状态标题后同一行显示 `2d 23h:44` 格式倒计时；剩余不足一分钟向上取整，小时和天正确进位，未知显示“-”。到零只更新显示，不自行改变服务端生命周期或抵扣金额；完整本地化时间保留在无障碍名称中。两张福利卡等高，设备图位于卡片底部光影上方。
- 异常1：Given 激活超时或读取失败 When 请求未确认 Then 保留错误与重试，不显示激活成功，不发新领取或赠送。
- 异常2：Given 抵扣/价格缺失、资格拒绝、库存不可购或容量已满 When 操作 Then 明确结果和恢复入口，禁止无效提交；未知金额显示“-”。
- 异常3：Given 购机中余额不足、报价增加或结果不明 When 确认 Then 保留既有失败反馈/原意图恢复，不创建第二订单，不把预计值作为扣款依据。
- 异常4：Given 确认后关闭页面或切换账号 When 原请求返回 Then 不把旧账号结果写入新账号提示；同账号再次进入以服务端状态恢复。

**③ 数据字典+生成规则**

| 字段 | 类型 | 生成规则/约束 |
|---|---|---|
| claimNo/version/state | string/number/enum | 服务端权威，客户端只读缓存，不自行生成正式领取单 |
| claimedAt/expiresAt/graceEndsAt/extendedEndsAt | epoch ms | 领取快照与服务端状态推进；EXTENDED仅延长抵扣保留，不继续产出 |
| shadowUsdt/shadowNex | number | 已累计试用收益，购前不属于可提现钱包 |
| offsetUsdt/remainderUsdt/priceUsdt | number | 领取快照权威金额；缺失不按当前活动配置反算可用值 |
| estimatedOffset | number | 配置日收益×领取时长再受配置上限约束，仅标预计 |
| eligibilityReason | enum | 既有原因及capacity-full，最终是否可领以canStart为准 |
| orderNo | string | convert原子交易返回；幂等重试复用原意图，不在客户端伪造正式订单 |

**④ 状态机+禁止动作**
ELIGIBLE → 确认/激活中（客户端瞬态）→ ACTIVE → GRACE/EXTENDED → FAILED；ACTIVE可主动取消至CANCELLED；ACTIVE/GRACE/EXTENDED可主动购机至REDEEMED。激活成功反馈不是新增业务态。禁止未读回成功显示成功、自动扣款、预计当余额、终态继续计入试用槽。再领资格沿用服务端冷却政策，本功能不修改。

**⑤ 多状态覆盖**
默认态展示真实状态与下一步；空状态为可领介绍或明确结束状态，不留空白卡。加载态保留布局骨架/已确认只读快照。报错态未知金额显示“-”，提供重试或设备管理出口；极限态覆盖长商品名、320宽、三语、明暗、最后一天与减少动态。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 |
|---|---|---|
| 首页领取 | 领取确认 | 查看产品、时长、预计值，关闭/取消可用 |
| 首页已领取状态卡整卡 | 试用详情/设备管理；符合再领资格时仍为领取确认 | 延续既有状态路由，移除重复独立按钮；错误重试不触发整卡路由 |
| 确认并激活 | start + state | 激活中→成功反馈；失败留原层重试 |
| 成功后查看设备 | /pages/me/devices | 试用行与正式设备分开 |
| 提前购机 | /pages/me/trial → /pages/store/checkout?source=trial | 原试用期内按服务端报价补齐完整试用权益并减固定立减（FEAT-TRIAL05，[方案](proposals/UVEL_试用提前转购权益衔接_20261027.md)）；到期后按已累计抵扣；实付复核、主动二次确认 |
| 结束/已转购状态卡 | 试用详情/设备管理 | 说明状态；不再次占位 |
| 读取失败重试 | state | 未确认前禁止支付或伪造余额 |

**⑦ 跨文档一致性**：主PRD §5.4、§5.6、§9.11、§11.1；结算复用现有convert原子链，金额以 state.quote / convert 回执为准（FEAT-TRIAL05）。领取不要求支付方式；正文旧绑卡/自动扣款叙述以本节现行契约为准。

#### [FEAT-TRIAL04] 试用机位与容量

**① 用户故事**：作为持有正式设备并正在试用的用户，我想在队列和设备管理看到试用机位，以便查看时间、抵扣与转购，同时保留所有已购设备。

**② 验收(GWT)+异常路径**
- Given 正式占槽数2、ACTIVE试用 When 查看首页/赚取/管理 Then 三处均为3/容量上限且只有一个试用行；不向正式设备数组注入伪资产。
- Given 正式占槽5且试用1 When 转购 Then 仍为6，试用行退出、真实设备增加一次；重复请求不重复扣款或造设备。
- 异常1：Given 已满容量 When 领取、普通激活或下单 Then 服务端拒绝额外占槽；现有已购设备不消失。
- 异常2：Given 试用读取失败 When 显示设备 Then 同账号已确认正式设备保持可见，槽数未知；试用金额未知、动作停用且可重试。
- 异常3：Given 到期或取消 When 服务端状态推进 Then 只释放相应试用槽，不删除已购设备；GRACE/EXTENDED继续保留一个抵扣槽直到终态。

**③ 数据字典+生成规则**：正式设备id/instanceNo来自设备接口；试用展示key为独立呈现标识，不用于设备激活/收益/任务接口。reservedTrialSlots ∈ {0,1,unknown}，只有已确认active/grace状态可计算，未知不得当0。

**④ 状态机+禁止动作**：沿FEAT-TRIAL03；CLAIMED/ACTIVE/GRACE/EXTENDED占一槽，终态零槽。转换在锁定账号的同一事务中置换预留。禁止重复占位、把Cloud Share误当物理槽、隐藏已购设备腾空间。

**⑤ 多状态覆盖**：默认试用行沿所在队列的普通设备行呈现机型，小图上方增加“试用”角标，标题仅机型名；确认运行显示在线，抵扣保留期显示离线，读取失败显示状态未知，右侧保留相应剩余时间。当前/预计抵扣、进度、规则及购机放在展开区或详情，不在默认队列额外展开。赚取页共用单行展开状态，试用与正式设备不能同时展开；首页整行进入详情。管理页试用与已激活设备合并显示，数量包含试用行；正式设备展开后保留规格、置换及停用操作，试用展开保留取消确认；待激活及状态待确认设备独立分组，接入入口位于设备列表之后。空状态没有试用行但保留正式设备或添加入口。加载保留已确认设备/骨架，报错在展开区提供重试且不把未知计数归零。

**⑥ 点击流矩阵**

| 触发 | 目标 | 反馈 |
|---|---|---|
| 赚取/管理试用行 | 原地展开或收起 | 赚取与正式设备互斥展开，明细与操作保持可达 |
| 队列试用详情 | /pages/me/trial | 同一领取单，累计/当前/预计分别标注 |
| 队列提前购机 | 试用详情→结算 | 沿同一权威链 |
| 首页管理 | /pages/me/devices | 试用和正式资产并存 |
| 取消试用 | 确认→cancel→state | busy防重复，失败保留状态与重试 |

**⑦ 跨文档一致性**：占槽单源供领取、设备激活、订单预留与设备收益投影共同使用；转购将预留换成正式设备，不与普通新增设备算法重复叠加。
