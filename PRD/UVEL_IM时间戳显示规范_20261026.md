# UVEL IM 时间戳显示规范

本规范适用于现有人工客服、专属客服及共用会话组件；不恢复已下线的 AI 入口，不改变消息顺序、回执语义或服务端会话归属。

## 展示层级

1. 消息流采用无底色的居中时间分隔，12px 辅助文字、正常字体字距。首次有效消息、本地日历跨日、与前一条消息间隔**大于或等于5分钟**时显示。发送者变化不单独制造时间分隔。
2. 每条非系统消息保留「作者 · HH:mm」的紧凑辅助行，统一24小时制。图片、商品推荐、链接和文字消息使用相同规则。完整日期、秒与时区偏移通过该辅助行的title及无障碍名称提供，不占据气泡宽度；系统消息保留自身语义，不伪造发送人或回执。
3. 连续消息同一分钟或不足5分钟不重复增加分隔。分隔是显示数据，不能成为业务消息、未读计数或入场动画对象。

| 相对本地日期 | 分隔格式示例（中文） |
|---|---|
| 今天 | 今天 14:08 |
| 昨天 | 昨天 23:59 |
| 前2至6个日历日 | 星期三 14:08 |
| 更早、同年 | 10月18日 14:08 |
| 跨年 | 2025年12月31日 14:08 |
| 服务端时间在将来 | 完整日期含年及时间；不改写为现在 |

英文、越南文按当前应用语言格式化日期与星期，不拼接中文。完整时间以实际输出为准；表中示例描述信息层级，并非固定业务时间。

## 数据与生命周期

- 输入沿用已解析的epoch毫秒。人工消息时间来自服务端createdAt；本地待发消息使用首次入队时刻。客户端不猜测秒/毫秒，不用读取、重试或已读时刻替换发送时刻。原服务端日期解析和异常响应门禁保持。
- 显示使用设备本地时区；日历日差按本地日期计算，不能用24小时相除判定昨天，避免夏令时的23/25小时日误差。日期格式与账户时区、语言互不混淆。
- 缺失、非有限或无效时间不伪造「刚刚」或1970。未知时刻形成分组边界，下一条有效消息重新标注；乱序时刻另外标注，不在展示层重排消息。相同ID回读替换，不能重复插入时间条。
- 页面可见时每分钟更新相对日期，跨午夜后最迟一分钟更新「今天/昨天」；返回前台立即刷新，隐藏/卸载停止计时。格式更新不触发消息动画、不重新读后台、不滚到底部。
- 历史前插重新计算页边界，合并不足5分钟的连续段。请求前保存首条气泡相对内容的偏移，前插后以新旧偏移差补偿滚动，包含旧首条时间条消失的高度变化；账号切换/离页/过期测量不使用旧偏移。
- 原生旧锚点测量为空、无效、超时或失效时，本次不读取并前插历史，保留当前内容和阅读位置，允许用户重试。测量失败不能当成高度0；合法测得的0仍能正常分页。
- 重试、发送失败恢复、服务端确认、已读更新不得把同一条消息当新消息重播。实时新消息仍按既有左右180ms线性动画进入，减少动态模式保持静态。

## 原型与验收

原型的「消息演示 → 时间分组 · 跨日与5分钟」提供三页24条消息，含跨年、近几日、昨天23:59→今天00:01、恰好5分钟、图片与商品消息。它是loopback演示数据，不向真人客服发送。

验收覆盖：5分钟前后边界、零间隔、跨午夜、夏令时、跨年、未来/无效时刻、系统消息、三语、320/390和明暗主题；历史页边界消除重复标记且阅读锚点保持；日期刷新不重播。实际完成范围和真机/真实服务未覆盖项写入审查报告，不能以编译通过代替运行验收。

## 参考与取舍

- [Element X Android #7349](https://github.com/element-hq/element-x-android/pull/7349)：借鉴时间间隔划分连续对话的原则；本项目明确选用“满5分钟”作为边界，未复制其气泡分组实现。
- [Tinode消息列表](https://github.com/tinode/webapp/blob/master/src/views/messages-view.jsx)：借鉴本地日期分隔与逐条消息时间分层，沿用本项目的Vue/UniApp消息模型。
- [Zulip时间格式模块](https://github.com/zulip/zulip/blob/main/web/src/timerender.ts)：借鉴日历日期、语言和时区分开处理以及相对日期更新原则。

实现使用已有平台Date/Intl和轻量纯函数，不引入另一套IM SDK或日期库，也不复制第三方源码。
